## 1. 接手时先知道这几件事

1. 项目要建设的是**可追溯、可规范入库、可展示及横向比较的ESG数据平台**。PDF提取是生产数据的手段，不能让“包容一切披露”的提取框架无限拖慢数据产品交付。
2. 工作分为三条相连主线：标准条款包 → 科学数据库及审核发布链路 → 独立数据展示产品。三部分已有工程基础，当前最紧迫的瓶颈是提取质量与成本。
3. 第一阶段必须保留当前E1—E3的**16个主要原编号、5个小号标准包**。这里的16项不是早期研究中另选的“16项MVP”；完整平台主要清单49项也不能自行缩减。
4. **核心条款属于标准包，主要条款属于平台阶段选择。主要条款必须是核心条款，但其他核心条款不自动进入本次提取。** ESRS 2/MDR按需支撑，不自动扩大输出分母。
5. 标准、数据库、前后端和唯一重任务队列已经建设；**真实报告端到端质量验收尚未通过**，不能因构建成功、测试很多或页面有数据而宣称业务完成。
6. 最新紫金2025任务已按用户要求停止。约79分36秒只保存14个Core值，且身份与来源出口仍不完整；当前没有运行或排队任务。
7. 下一步已经有详细升级规划，但**尚未实施**：有界取值范围、同表一次理解、统一真实输出协议、程序绑定原值、成功片段立即交付。
8. 公开产品`PlatESG`与内部工作台`ConsoleESG`已经独立。不要把队列、错误、审核凭据和标准编译信息放回产品网站。

## 2. 项目目标与交付定义

### 2.1 最终要解决什么问题

从企业可持续发展/ESG报告中获得定义明确、来源可核验的数据。使用者可以找到企业和指标，查看年度变化，了解口径和原文，在满足比较条件时横向比较，并通过固定数据版本的API或导出复现分析。

数据不能只是“公司、年份、指标、一个数字”。至少要区分测量主体、期间、报告边界、方法、必要维度、原值、单位、来源、审核、修订和发布版本。集团与子公司、取水与耗水、范围2地点法与市场法、原始披露与推导结果不能混在同一概念中。

### 2.2 近期优先级

用户当前要求是尽快可靠跑通：

```text
PDF → OCR → DocumentIR → 16项主要指标定向提取
    → 可审核事实 → 规范候选入库 → 审核与发布
    → 独立数据网站展示、趋势及条件化比较
```

先把这些基本指标提取准确、快速、可审核，再扩大行业指标和全部数据点。不是先建一个全能Agent，再期待它自然交付产品数据。

### 2.3 三项建设任务目前到哪里

|主线|已建设基础|仍需完成的交付|
|---|---|---|
|标准条款包|E1—E3、ESRS 2、MDR作者源、编译、注册、核心/主要分层及未来占位|真实语义/提取验收，逐批业务成熟；占位不等于已建包|
|数据库及连接|指标字典、来源存储、候选导入、独立审核、口径、发布outbox及冻结版本|同一真实报告从合格提取到审核发布的完整验收；真实PostgreSQL部署验证|
|独立数据平台|PlatESG产品网站、公开API、趋势/比较/来源/导出；独立Console操作台|真实发布数据填充、效果与可比性验收，之后再做生产身份与规模优化|

近期完成的判断标准是：一份新报告的16项都有明确处理结论；存在合格披露的项目可形成身份完整、来源准确的候选；缺口和冲突被如实表达；审核后的数据能规范发布并被产品读取。**不能要求每份报告16栏都有数字，也不能用其他概念填空。**

## 3. 已确认的用户要求与工作边界

- 一个披露小号一个标准包，例如E1-5、E1-6、E2-4。保留原数据点编号，不用新内部缩写替代用户可见原编号。
- 包内核心、平台主要、语义角色和执行依赖分别定义。用户可选择只提取主要或核心范围，不自动提取整个标准全集。
- E1—E3先建设，E4—E5、S、G及其他框架保留清楚占位；ESRS 2/MDR被调用时必须有明确接口及版本。
- PDF及其多个OCR/IR版本应显示继承关系。报告处理是一条连续OCR→IR流程；选择PDF表示要处理该报告，选择固定IR表示复用该报告的一份证据，二者不是平行的无关资产。
- 工作台必须有真实状态与操作，悬浮窗显示处理状态。中文阶段、当前模型调用、已保存成果和缺口应来自后端，不能流于形式。
- 删除、残留记录及资产管理要直观。用户明确不希望继续投入繁琐归档；现有归档/回收实现属于历史工程，不能把新增这些功能当成本轮目标。删除问题需按实际记录与依赖核查，不得写成“所有记录都已可随意删除”。
- 批量自动生产要能冻结报告顺序、自动排队、连续处理和提取；人工审核/发布仍是独立环节。
- 模型按任务能力选择，允许Qwen承担适用的理解/视觉/抽取，不强制双模型，不静默换provider或发起云调用。
- 每个标准包是独立任务，享有完整独立模型额度；共享证据、缓存和唯一机器槽不代表共享报告token池。
- `CrawlESG/`是独立保护区，本轮不修改其代码、数据或文档。爬取/Kodo生产接入不属于本次提取内核修整。
- 保留已有工作树改动，不重置、不覆盖用户工作，不自行提交或推送。完整历史源码逐字回滚不再作为推进前置条件。
- 真实OCR/模型提取和业务审核发布由用户发起，或在其明确授权范围内执行。后续测试不使用失败中国石油中间结果；旧紫金结果也只是只读经验材料，不应直接固化成自动测试夹具。
- 凭据不得写入文档、任务JSON、日志、URL或公开前端。文档只记录获取位置和用途。

这些要求来自用户当前工作方向。旧规划中的“全量优先”、归档投入或曾经的MVP选择若与之冲突，不继续沿用。

## 6. 报告处理、定向提取和成果含义

### 6.1 报告与固定证据

PDF SHA确定文件字节身份；报告登记确定标题、发行主体、期间等业务身份；测量主体另行确认，不能把报告发行者自动赋给每个表格值。

一个PDF可以有多次OCR、多个IR及修订。OCR保存解析器原始结果、逐页内容、图像和manifest。DocumentIR把正文、表格、单元格、列头、脚注、章节、跨页和坐标组织成统一证据。**仍需要DocumentIR**，但前端应把OCR→IR作为连续报告处理，不要求用户理解两个割裂工程任务。

当前合同为`ocr-package-v1`、`document-ir-v0.12`及`document-ir-package-v1`。基础处理不默认全报告VLM增强。来源修正生成明确新revision，不能覆盖历史固定IR或偷偷换到“最新版本”。

### 6.2 执行组织

报告父Session协调各小号包任务；OCR、IR与提取共用唯一队列及一个重任务槽，父计划自身不再占第二个模型槽。

当前路由根据标准合同和实际来源选择直接表格`table_series`或来源Agent。已实现直接路线，但门槛仍过窄：要求`dimensional_table`，导致numeric能源表仍走Agent。该限制是待修问题，不是未来设计原则。

检索结合关键词/BM25、Qwen3 Embedding和RRF等能力。模型承担语义解释，程序承担真实引用、结构/身份合同、预算、持久化、确定性单位和公式操作。模型角色可选择，不按包名、公司名或失败次数偷偷切模型。

### 6.3 成果层次

|对象|含义|
|---|---|
|SourceFact|报告实际披露的中立事实，包括暂时没有标准映射的已读行|
|Requirement mapping|该事实与某条原编号的关系和依据|
|Core|按提取合同组织的定量、定性、属性、维度及证据记录；不是正式发布观测|
|Checkpoint/阶段快照|执行恢复和阶段成果材料；存在文件不等于质量合格|
|Result Bundle|固定机器交付合同`targeted-result-bundle-v1`；partial也可作为明确部分成果|
|候选入库|交付到数据库等待事实、映射与口径审核；不自动批准|
|规范观测|满足发布条件后的正式数据，属于冻结数据版本|

应分别表达执行状态、覆盖、事实质量、映射、审核、发布和可比性。未执行、预算失败、限定证据内未找到、来源冲突与未披露不是同一个状态。当前增量保存仍有断点，见下一节。

## 7. 数据库与审核发布连接

### 7.1 技术选择

正式数据库语言/方言已选择**PostgreSQL SQL**。本地使用PGlite，生产适配使用`pg`驱动；真实PostgreSQL服务器部署、权限、备份恢复及负载尚未验收。SQLite是执行控制面存储，不是正式ESG事实主库。

高频身份使用明确类型化列，长尾结构使用JSONB，披露原值保留文本，规范数值使用精确`numeric`。API和JSON导出以十进制字符串返回精确值，图表坐标才转浏览器Number。

### 7.2 现有数据层次

|层次|实际对象例子|职责|
|---|---|---|
|不可变来源|PDF、OCR、IR、Bundle|重现原文、证据与版本|

### 7.3 从提取到产品

Console明确选择报告身份、修订、主体及固定来源后交付Bundle，服务端校验并保存幂等回执。导入形成候选和来源快照，之后分别审核事实、映射和口径。审核决定与待发布outbox同事务保存；处理器检查门槛，通过后形成规范观测和冻结版本。

`PLATESG_AUTO_PUBLISH=0`表示暂停自动消费事实事件；具备发布角色的人员可以显式处理。设为1也不跳过发布门槛。网络超时后可能存在不确定提交，应按同一回执核对，不换ID重复导入。

公开产品读取冻结版本，不能直接查询“所有approved候选”冒充正式数据。比较需再次检查期间、边界、方法、单位及维度，返回排除原因；同一企业同年可能有多个合法口径。原始披露可展示不代表自动可以排名。
