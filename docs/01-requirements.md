# 产品与需求

## 目标与范围

以完整报告和独立条款为输入，经可重复、可中断续跑、成本有界的链路，产出可追到原文的原值。独立数据库接收后按明确政策组织产品，Console操作，Plat公开展示。条款、报告、阅读器、应用和数据库通过合同合理连接、独立演进。

范围包括条款管理、PDF资源、物理证据、两类提取、编排、交接、数据库投影、显式发布和展示。CrawlESG不接入。自动抓取、向量召回、条款成熟度/样本配额和自动发布不作为当前主干的完成条件。

## 要求及可观察行为

| 编号 | 要求 | 完成表现 | 责任 |
|---|---|---|---|
| RQ-01 | 单条内聚 | 一个clause.json提供定义、类型、属性、词典、检索、阅读、证据、用途和展示；新增条款不写指标专用分支 | ClauseESG |
| RQ-02 | 同一主干 | quantitative/qualitative决定两类协议；16/32等只是ID集合 | extraction |
| RQ-03 | 原值优先、属性包容 | 种类、量、单位有安放位置；单位/主体/期间未知也保存实际值；丰富属性按字段保存 | contracts、binding |
| RQ-04 | 全披露期间 | 2023/2024/2025各自保存；季度、财年、区间、时点和未知保留含义；主报告年不筛值 | binding、database |
| RQ-05 | 来源可靠 | 数值来自实际单元格/文字，引句来自原文；目标定义不能冒充报告披露 | document、binding |
| RQ-06 | 条款驱动搜索 | 页定位、对象检索和补读词消费所选条款；文档服务不内置ESG词库 | ClauseESG、document |

| RQ-08 | 模型可解释 | 实际模型、模态、预算、tokens、耗时和失败可查；本地执行，不静默切云，不跨条款复用理解 | runtime及消费者 |
| RQ-09 | 批量可管理 | 报告独立成会话，共享资源协调；取消包含阅读与准备；断连保留进度，不伪报完成 | pipeline |
| RQ-10 | 独立交接 | 封存包可以离开生产目录传输；接收有幂等回执；内部路径不是接口 | extraction、database |
| RQ-11 | 数据职责分层 | 原值保留所有期间/来源；比较、选源、重述、发布不反向删除测量 | database |
| RQ-12 | 清楚的操作界面 | 五类对象及父子页面、统一运行浮窗、按需分页结果表 | Console |

| RQ-14 | 统一维护 | 一套当前文档；同轮修改责任模块、合同和文档，移除替代内容 | 全仓库 |

## 术语与状态含义

资源信息描述报告企业、发表年、行业和文件身份；实际身份描述某值的期间、主体、场址、边界和方法；目标描述条款要找什么，三者不可代填。

事实是带证据的原值；条款关系是match/uncertain/different；覆盖是计划范围内的搜索结果；比较资格归数据库；发布是操作员采用明确成员/政策建立的产品。执行完成不等于全部条款披露、全部属性已得或内容全部正确。

## 使用过程

1. 制作/选择独立条款，导入完整PDF及已知资源资料。
2. Console预览并创建会话，冻结输入与条款。
3. 定位必要证据、读取各期间，保存两类事实及关系。
4. 封存并交接数据库，查询接收、投影和原值。
5. 预览成员和选源理由，显式发布，Plat读取发布快照。

RQ-01—14已有对应实现入口；不同报告形态的效果仍须依据真实任务判断。现有缺口集中在[质量与工作清单](10-quality-and-work.md)，不再把每次故障另立为总规划。
