## 2026-10-24（第二十二轮）：按操作顺序逐份报告跑“全部定量”，修守卫与派发竞态

按“选报告 → 全部定量 31 条 → 提取 → 看结果”的顺序，一份一份换成新样本迭代链路：隆基 2025、中国石化 2025。
所有修复都在守卫数据与队列身份层，没有为任何报告写特例。

**隆基：四个可泛化问题**

- **目标/进度行被当成实测值**：SDG 进展表里的“到 2030 年…排放强度相比 2020 年下降 52%”被映射成排放强度。
  新增通用规则：含“较/相比 20XX 年下降 N%”或“到 20XX 年实现…”的行是计划或变化量，任何条款都不接收。
- **管理层级混入高管比例**：“初级管理层”“创收职能管理层”的女性比例被当成最高管理层读数并互相冲突。
  这类行改为 `label_not_top_management_level`，作为同一披露的相关度量保留为子项；同时补上“相关度量行”的
  自动恢复，模型漏映射时也能进入子表。
- **方向不对的子项**：“天然气/原煤消耗”曾被挂到“可再生能源”下。子项关系现在按条款自身主题排除
  （`METRIC_CHILD_EXCLUDES`）：化石载体只属于化石能源，可再生载体只属于可再生能源。
- **电量单位换算错误**：`亿千瓦时` 被按 TWh 计（差 10 倍），且 `亿度/万度/千度/度` 不识别；
  已修正提取侧尺度，并把中文口语单位加入单位规则 **1.5.5**（旧版本保持不可变）。

**中国石化：单一口径冒充总量、处理量冒充产生量**

- 原油消耗量被当成化石能源总量；工业取新水被当成取水总量 → 单燃料、按水源/用途的取水均按分项处理。
- “总废弃物处理量/总危险废弃物处理量”被当成产生量并互相冲突 → 处理/处置行不再算产生量。
- 流失率冲突来自“男性/女性/年龄段/基层/中层管理者”子人群 → 这些人不再与全员流失率互相冲突，保留为子项。
- “固体废弃物量”这类未写“总”的废物流按类别处理，E5-5_07 在没有产生总量时如实显示“已找到分项”。

**链路竞态：同一计划步骤被派发两次**

- 真实运行里出现过 `Native task already has an active queue entry` 与 `UNIQUE constraint failed:
  idx_pipeline_plan_step`：请求线程与协调线程同时推进同一步，第二次派发失败并把整份文档判失败。
- 队列现在以 **计划步骤键** 作为派发身份：同一步骤的第二次派发直接采用已存在的队列行；
  派发抛错时协调器也先按键查找并采用已有行，而不是让文档失败。步骤键与原生任务同进同出，不再重复建会话。

**实测**

- 隆基 2025：31 条全部产出结论（16 找到、5 待复核、8 未披露、2 仅有被拒），无冲突；管理层级进入子表。
- 中国石化 2025：12 找到、3 待复核、16 未披露、0 冲突；E5-5_07 如实标记“已找到分项”，危险废弃物、取水、流失率不再误判。
- 测试：提取 754（6 跳过）、文档 660、Console 212；服务按发布指纹协调重启后运行。

## 2026-10-24（第二十六轮）：审核前先读证据，把已读到的轴用起来

这轮不靠视觉模型重读原文，也不靠人工补表：提取其实已经读到了污染物、范围、类别、方法、分母、
边界等轴，但审核层只接受平台的 canonical 维度、键名也对不上，结果把证据丢掉了，逼人重新选。
现在先修这条“证据 → 维度”的断点，再让指标定义承担它本来就该承担的固定含义。

**新增证据轴解析（`database/scripts/review-evidence.mjs`）**

- 来源身份（`source_identity.identity_raw`）、原始维度与行标签/声明文本统一归一为指标维度代码：
  污染物（SO₂/SOx/NOx/VOCs/PM/COD/氨氮/重金属/硫酸雾等）、介质、温室气体范围、聚合层级、
  范围三类别（编号与名称）、合并方法、测量方法、分母、毛/净额、统计时点、人群、
  危险分类、性别、管理层级、离职口径、培训范围、事故率分母与倍数。
- 每个值带来源（`source_identity` / `extraction_dimension` / `row_label` / `metric_label` /
  `definition_fixed` / `definition_policy`），提案返回 `dimension_sources` 与 `unstated_dimensions`。
- 只认原文明确写出的词：没有归一规则的自由文本不会变成维度代码；“来源没说”保持未决，不猜。
- 边界同义词归一：`集团合并口径/合并报表范围/本集团/consolidated` 等 → `group`；
  其余（含子公司、基地、地区）→ `part_of_group`，仍按更窄范围导入。

**字典 1.4.5（链表变化，产物不变）**

- 15 个陈述型指标声明 `unresolved_dimension_policy: not_stated`：来源未陈述的轴如实记录，
  可展示但不进入同口径比较；不再因为缺 `policy_scope` 之类的人工输入而阻塞整条披露。
- 12 个指标补齐“定义性固定轴”：范围三总量（`total/total`）、危险废弃物（危险/总量/总计）、
  二次材料占比、未回收废弃物占比、最高管理层女性占比（management/female/top_management）、
  按性别/人均培训（employees/by_gender 或 all_employees/per_employee）、工亡人数、
  歧视事件、董事会女性比例、已确认腐败事件、消费者投诉等。这些轴由指标本身决定，不应由人再选。
- 字典 schema 补 `unresolved_dimension_policy`，历史字典留在 `catalog/history/`。

**机器核验 v2**

- 陈述型指标不再检查单位（文本核对即可）；候选查询同时读取 `qualitative_claims.statement_raw`。
- 未陈述轴（`not_stated`）可批准但发布评估标记 `unstated_dimension:*`，比较资格为不可比。
- 审核记录写明边界来源（原文集团口径 / 原文更窄范围 / 报告主体为子公司）与未陈述轴；
  审核界面预填提示同步显示“未陈述轴按定义记为 not_stated，不进入同口径比较”。

**真实数据核验**

- 紫金矿业 2025 E2-4 真实提取包：18 条来源事实中 16 条带 `identity.pollutant`；
  旧逻辑会忽略这些身份值，要求人工为每条选择污染物；新解析 **16/16 全部归一**
  （氮氧化物、二氧化硫、颗粒物、氯化氢、氨气、硫化氢、硫酸雾等），并同时补出 `pollution_medium`。
- 该历史包本身没有注册的 import-only 契约，未导入发布库；核验直接读取其 `source-facts.json`，
  不改变发布库。真实库仍为“字典 1.4.5 + 产物 0 + 数据集 0”。

**为什么没有引入视觉模型**

- 这些轴已经在提取阶段由页面读取与结构证据写入来源身份，并带页/坐标；再用视觉模型读同一单元格
  只会增加模型成本与不一致，不会得到报告没写的信息。
- 视觉模型仍用于页面读取兜底；审核链路通过“证据轴 + 定义固定值 + 明确未陈述”减少人工，
  新增条款只需要在字典声明固定轴或 `not_stated` 策略，不需要为报告或条款写分支。

**测试**

- 平台 Node 67（57 通过、10 跳过；新增 9 个证据轴测试、9 个候选/边界/陈述型核验测试）；
  平台 Python 77；数据库 57（55 通过、2 跳过）；Console 217；`tsc -b` 与前端构建通过。

  （不跑行触发器、不级联）表达“产物纪元重置”，并在提交前比对链路表数量，任何一项变化即回滚。

  字典未变化时启动不再补发字典待发布事件。因此清理后重启仍为“数据集 0、产物 0、事件 0”，

[待审核候选审计](PUBLICATION_REVIEW_AUDIT_2026-10-24.md)。

**共性原因**

- **90 条从未审核**：导入把每条映射一律写成 `partial/unknown`，并留下“需独立业务审核”的说明；
  事实与映射本身并未被判错，但既没有审核动作，也没有可用的测量口径建议。
- **3 条来自旧标准包版本**（2.1.1）：当前字典定义已是 2.2.0，批准旧事实不能改变其版本身份，只能按当前版本重新交付。
- **1 条只缺测量口径**：事实与映射已批准且关系为 exact，补口径即可发布。
- **全部 117 条缺来源期间**：历史导入没有把报告身份的报告期回填到事实。

**链路增强（与报告、条款、平台解耦）**

- **导入期映射判定**：`import-bundle.mjs` 由提取证据决定映射关系——守卫接受且未标子范围 → `exact/supports`；
  原文写明子范围 → `narrower/partially_supports`；其余保持 `partial/unknown`，并把判定规则、观察状态、原文边界写进映射理由。
- **报告期回填**：事实没有日期时采用报告身份的报告期，来源身份记录 `period_source=report_identity`。
- **证据提案**（`database/scripts/candidate-review.mjs`）：为每个候选计算实体、期间、边界、测量方法、单位与维度；
  定义固定值或唯一允许值自动填入，其余列为“仍需人工确认”，不猜。
- **机器核验 v1**：只批准全部发布条件都能被证据证明的候选（指标就绪、映射 exact/supports、有原文来源、数值可核、
  期间可证、主体已登记、边界可证、单位可换算、维度齐全），并把规则版本与依据写入审核记录；发布仍由操作员触发。
- **接口**：`GET /internal/v1/candidate-proposals`、`GET /internal/v1/candidates/{id}/proposal`、
  `POST /internal/v1/machine-verification`（默认 dry-run，`apply=true` 才写入）。
- **操作台**：发布中心新增“机器核验”面板（先展示可批准条数与仍缺证据的原因，再提交）；
  审核表单按提案预填主体、期间、边界、单位与维度，并说明预填依据与仍需人工确认的项。

**实测**

- 交付宁德时代 e1-6 的 9 条事实：6 条 `exact/supports`、3 条 `narrower/partially_supports`，报告期自动回填。
- 机器核验：3 条直接批准（范围一、范围二地点法、范围二市场法）；6 条保留人工：3 条子范围需确认边界、
  1 条范围三需类别与聚合层级、1 条排放总量需合并方法、1 条强度分母与平台定义不同且单位不可换算。
- 历史 117 条中 9 条本身口径完整；其余需按新链路重新交付，旧映射缺少证据判定，不能凭现有数据臆断为 exact。
- 平台处理器此前处于自动模式，演示批次核验后的 3 条被自动发布；已按既有约束改为 `PLATESG_AUTO_PUBLISH=0` 并重启，
  之后机器核验只批准候选，发布仍需显式“处理待发布事件”。
- 测试：数据库 55、平台 Node 34（+5 新）、平台 Python 73、Console 216、类型检查通过。

## 2026-10-24（第二十一轮）：两次失败提取的根因修复与成果页重排

三份真实报告（宁德时代、紫金矿业、越秀地产）按“全部定量 31 条”运行，两份失败。逐条查证后修复的是链路本身，没有为任何一份报告写特例。

**失败一：紫金 `ResultContractError`（重复观测主键）**

- 根因 1（语义层）：当一个指标只有“部分/子范围”读数时，`consolidate` 既把它当作主值（标记
  `only_part_of_group_disclosed`），又为同一个单元格生成一条“其他口径”视图；两行主键因此相同。
- 根因 2（语义层）：同一数量的不同单位写法（`3,400,000 tCO2 e` 与 `3.40 百万tCO2 e`）因“边界未知”被拆成
  主值 + 视图，而它们本是一次披露。
- 根因 3（成果包）：`views` 的写入循环嵌在成员循环里，一个有多个成员的条款会把同一视图写多次；
  `result_count` 又按写入行数统计，和按主键去重的事实数不一致。
- 修复：视图改为在成员确定后统一生成，只保留与成员读数不同的口径；边界未知但数量相同的读数并入具名口径；
  成果包每个条款只写一次视图，并按派生主键去重（同一读数重复到达只写一行），计数即实际写入数。

**失败二：越秀 `IR requires review`**

- 根因：第 28 页一个装饰性 `(cid:28595)` 字形的包围盒宽度为零，被判为**全篇**坐标合同失败，
  `readiness=failed`，整份报告不可提取——而其余 399 个块与 36 页文本都可用。
- 修复：零面积包围盒降为对象级警告 `degenerate_bounding_box`（带对象与页码），只有坐标系统缺失/错页/越界
  仍按全篇阻断。实测越秀同一份 IR 复核为 `ready_with_warnings`，36 页全部可用。
- `waiting_review` 的说明现在带上 IR 编号、就绪状态与证据策略原因，不再只有一句“去 04 修复”。

**解耦与隔离**

- 一个标准包写出非法成果包时，只把该包任务标为失败并继续写其余包，报告会话按“部分成果”结束；
  条款包之间、包与报告之间不互相拖垮。

**成果页重排（前端）**

- 删除与顶部导航重复的四步链路条；会话页只保留状态与记录管理，交付动作移入“交付审核”页签。
- 成果页改为整幅表格（条款 / 指标 / 状态 / 主值），行内展开主值、子表、其他口径、来源明细、陈述与未采用候选；
  不再用窄栏挤压编号与标签，页码、子项、口径数收进指标下方小字。
- 导出 CSV 从页头主按钮降为工具行里的次要动作。

**验证**：提取 725 通过（6 跳过）、文档 659、Console 212（删除 3 项链路条测试）、类型检查通过；
紫金原失败任务恢复后 16 个成果包全部写出（29 条事实、49 条证据），越秀按新规则重跑。

## 2026-10-23（第十五轮）：同一指标的多口径自动拆成多行

报告常把同一个指标按不同范围披露（集团总量、某生产基地、子公司、海外）。此前链路只取一个，
另一个要么进“相关子口径”只作展示，要么被丢掉。这一轮把它变成一等公民：

- **提取**：识别印在行标签、分区标题里的范围词（集团/合并、生产基地、子公司、海外、香港、内地），
  同一条款下不同范围各自成为一条结论视图（`views`），不再当成冲突彼此压制；正文里明确标注为
  “其中/部分”的子范围同样独立成行。
- **模型漏给列时按表头年份取列**：此前整张表会被丢弃（宁德第 72 页的基地排放表就是这样漏掉的）。
- **成果包**：每个视图写一条事实，带 `reporting_boundary`（如 `part_of_group`），来源与页码独立保留。
- **数据平台**：`reporting_boundary` 随事实身份进入候选；口径表单自动预填边界，两个范围可以分别
  审核、分别发布——观测身份本就包含 `boundary_code`，所以两条观测并存，不会互相覆盖。
- **操作台**：指标成果里显示“同一指标的其他报告口径”，交付面板标注证据偏弱的报告期。

实测宁德时代：E1-6_12 同时给出集团总量 117,026,505.54 与基地 1,751,599.73，范围一同样是两条；
交付后是两条独立候选，边界由审核人确认后分别发布。

## 2026-10-21/22（第四轮）：标签列误判、成员补全与声明式条款规格

本轮从一个真实失败出发：中国石油 2025 报告 96 页只抽出 2 项，且第 91 页“业绩数据”表的
NOx 数值明明存在却整表未被映射。查到的根因不在模型，而在更上游的表格解析。

- **带单位的行标签不再被当成单位列。** `氮氧化物（NOx）排放量（万吨）` 这类标签以
  `（万吨）` 结尾，旧判定只要出现单位词就把整列当单位列，结果整张表没有行标签，
  模型无从映射。现在要求单位列本身就是单位；括号后仍有实义词的属于标签列。
- **污染行按标签补回。** 整表漏映射时，程序按污染物词表（NOx、SOx、VOCs、COD、氨氮…）
  提出行级候选，仍由同一套守卫决定接受、复核或拒绝，并标 `row_label_names_pollutant`。
  不虚构数值，只指向表格实际打印的行。
- **拒因进入成果。** `brief()` 保留 `rejected_by`，结论附带 `rejection_reasons`；
  “仅其他期间”不再掩盖“范围一+范围二合并行”这类真实原因。
- **可扩展属性。** 每个成员携带 `attributes`：列标题路径、表标题、分区、单位来源、
  边界与期间标签。开放字典，后续解析器或模型可继续扩充，不改合同。
- **条款泛化。** 新增声明式 `ClauseSpec`（必需词、排除词、单位维度、总量约束、分项词）。
  16 项保持既有专用守卫，未预置条款走规格层判定，不再无条件通过。新增条款只需声明，
  不改守卫代码。

## 2026-10-18（第三轮）：宽表跨页续接与显式 Total 列

- **横向跨页续接。** 超过一页宽的表格常跨左右两页排版：左页有行标签和首批实体列，右页只续实体列、重复年份。此前跨页链接要求两页列数相同，这类表永远连不上，模型只读到左页子实体列。现在按结构判定并标记为 `horizontal` 续接：左页首列是文字标签、右页首列是数值或为空、两页前几行重复至少两个年份、垂直版面带重合。判定不依赖任何具体报告，命中的组会写 `cross_page_columns_appended`。
- **按首个数据行对齐。** 两页的表头行数不一定相同（左页多一行分区标题），逻辑表分段各自记录 `row_offset`，按“含数值之前的行都是表头”推导，数据带行数不一致时保留 `horizontal_row_alignment_unresolved`，不强行配错行。
- **提取侧合并视图。** `composed_tables` 把同组的物理表按列拼接成一张视图再提取，每个单元格保留原 `cell_id` 与页码，证据仍指向数值实际印在的那一页。
- **表头带判定。** 表头里的 `(3)` 这类脚注标记不再被当成括号负数而提前结束表头；存储的 `header_row_indices` 只标第一行时，仍按数值行之前的行补全年份行。
- **显式 Total 列。** 同一期间下存在唯一以 Total 命名的列组时，取该组对应该期间的列，而不是模型选中的分部列；实体列不一定能相加（边界可能重叠或嵌套），因此不再依赖列求和判断。切换时写 `column_switched_to_explicit_total`。
- **实测。** CKH 附表从 11 项提升到 16 项，Scope 1/2/3 取到集团 Total 列（6,734,455 / 2,236,657 / 11,691,966）；9 份金标报告 157/159 持平，0 错 0 漏，两处已知偏差不变。
- 记录：系统状态（已归档到 Git 历史）。

## 2026-10-17（第二轮）：PDF 文字层直读，扫描件选页

- **数字版 PDF 不再逐页送视觉模型识别。** foundation16 定向识别先用 OCR 流水线自带的版面模型（PP-DocLayoutV3，CPU）找出各区域，再按区域从 PDF 文字层取字、按字形几何重建表格（列投影、表线分行、跨行类别单元格、分组表头、上标脚注）。只有文字层不可用的页（扫描页、图片表格、字体无法映射、倾斜文字）才进入 PaddleOCR-VL。成果仍是同一 OCR 页面格式，IR 及之后的环节不变。
- **扫描件选页。** PDF 没有可用文字层时，用 macOS 自带的 Vision 文字识别（本机运行，不联网）读出每页文字，再按同一套关键词打分选页，不再整本送视觉模型。
- **标题图片。** 文字层为空的标题区域先用 Vision 补读；读不出文字的装饰图形不再迫使整页走视觉模型。
- **提取规则。** 表注按表格引用的脚注编号匹配（跨栏续表取另一栏的同号注释，双栏各自编号时只取本栏）；行名称即指标标准名称、模型漏映射时按规则补充为待复核（即使模型把该指标映射到了合并行，也仍按标准行名取那一行）；“设备回用量”等非水对象不算循环水；正文补查只读含对应单位数值的段落或明确的方法陈述；数值后的上标脚注不并入数值。
- **范围 2 方法。** “电网平均排放因子”在两种核算法下都会用到，因此只有行名称本身这么写时才算位置法；注释里的因子说明不再把市场法数值判成位置法。
- **污染物方法陈述。** E2-4_09 的提问规则只在请求该指标时出现，模型不再为空指标空转；方法陈述识别覆盖“排放量计算公式”“估算”这类不点名单一污染物的注释。
- **工作台。** 16 项看板显示各页的读取方式（文字层直读、本机识别、视觉识别页数）。
- 实施记录：16 项快速链路（已归档到 Git 历史）第二部分；实测数据与已知问题见系统状态（已归档到 Git 历史）。
