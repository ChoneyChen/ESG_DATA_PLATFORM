# 阶段 13：草稿提升为新包版本，并跑通试点提取

日期：2026-10-28  
范围：`ExtractESG/standards`（提升编译）、定向提取与文档 API、Console 条款编辑器、真实试点运行。

## 1. 提升做了什么

```text
clause-drafts/<id>/           作者编辑、已校验
   └─ promote()               复制 authoring 源 → 新版本目录
                              改写 manifest.package_version
                              只把包能承载的概念字段写入 metrics.json
                              （正向定义 / 易混概念 / 排除条件）
                              StandardPackageCompiler 编译并逐字段回读校验
        ├─ releases/<pkg>/<v>/package.json     新版本发布产物
        ├─ registry/releases.json              追加一条 compiled_draft
        └─（可选）registry/.../registry.json    切换当前版本，默认不做
```

三条硬约束：

1. **不改不可变包**：新版本是新目录、新摘要；旧版本原样保留。
2. **不自动切换**：`activate=False` 时平台当前标准仍是旧版本，只有显式开关才会改 pin。
3. **只提升包能承载的字段**：检索词、口径等属于编译产物，不写回包；
   草稿里只改这些时，提升会被拒绝（`Draft makes no change the package can carry`）。

## 4. 验收记录与生命周期

验收从冻结成果包计算，绑定 2.1.3 的合同摘要（`6e57e9c50cef…`）：

| 试点 | 结论 | 生命周期状态 |
|---|---|---|
| 3 | rejected（事实全为上一年度分项） | `trialed` |
| 4 | **accepted**（任务已执行、事实绑定、属于报告当期、证据有锚点、单位期间完整） | `accepted`（缺业务批准，不标可发布） |

条款中心现在同时列出 `2.1.2`（当前）与 `2.1.3`（试点）两个版本，各自独立的 23 条条款状态：
2.1.3 为 22 条 `compiled` + 1 条 `accepted`。

### 过程中修复的两个真实缺陷

1. **partial 任务被当成"未执行"**：标准路线在对象未全部解释完时任务状态是 `partial`，
   但它确实执行并绑定了事实。验收改为 `completed` 与 `partial` 都算已执行，只有 `failed`/`interrupted`/`cancelled` 才算未完成。
2. **事实期间不是报告当期也算通过**：新增 `current_period` 必需检查，报告期优先取运行声明的期间；
   试点 3 因此被正确判为未通过。验收记录增加 `schema_version`，旧记录按 1.0 规则继续有效。

（试点 4 曾用旧评估器写入一条 rejected 记录，确认由上述缺陷导致后只删除了这一条本会话产生的记录并重新计算；
此前 252 条历史记录保持原样。）

## 8. 切换当前标准（2026-10-28 已完成）

试点通过后执行了显式切换：

```text
POST /api/pipeline/standards/esrs.2023-set1.e1-5/2.1.3/activate
→ {"from_version":"2.1.2","to_version":"2.1.3","source_digest":"a94737a6…","changed":true}
```

切换后的真实状态（全部来自运行中的服务，不是推断）：

| 检查点 | 结果 |
|---|---|
| 标准目录当前版本 | `esrs.2023-set1.e1-5` = **2.1.3** |
| 发布索引 | 2.1.2 `active=false`、2.1.3 `active=true` |
| 平台主要 profile | 该包固定为 2.1.3，摘要 `a94737a6…` |
| 兼容检查 | `ready=true`，无阻塞 |
| 条款生命周期 | 2.1.3 为当前版本，其 `E1-5_01` 为 `accepted` |
| Console | 标准中心显示 `E1-5 · v2.1.3`，2.1.2 标为“非当前版本” |

切换的安全边界：

- 只允许切到**已登记、未退役、摘要与索引一致**的版本；
- 旧版本不删除，冻结任务继续按各自的 `runtime_digest` 读取；
- 切换后运行时指纹变化，服务需重启一次（本次已重启并通过兼容检查）；
- 尚未切换的包仍保持原版本，切换是逐包动作，不做全库批量替换。

**没有跟着改的**：平台字典仍是 1.4.5。字典是**已发布指标定义**的权威，换字典等于发布新版本并让已发布观测
与旧定义脱钩，必须作为独立、可审计的发布动作，不由标准切换顺带完成。

### 一处必要的迁移

数据库此前按“同一 `clause_version_id` 内容不同即拒绝”保护条款版本。标准包没有变、只是编译器修复导致
profile 摘要变化时，这条规则会误伤（本次 2.1.3 投影时触发）。迁移 0017 增加 `package_source_digest`：

- 包摘要不变 → 允许更新投影摘要（记录为重新编译）；
- 包摘要变化 → 仍拒绝（同一 id 指向不同条款）。
