# 提取出口、审核、发布和数据库对接方向

日期：2026-10-30。**本文是后续建设方案，本轮没有实现接收器、SQL 迁移、审核页面或发布流程。** 当前范围止于 PDF、来源事实、条款映射、范围确认与组织结果。

## 1. 稳定输入边界

后续消费者通过提取服务 API 取得运行事实包、独立事实、冻结条款和组织结果。交接标识至少包括 PDF 编号/散列、运行编号、IR 修订、引擎指纹、条款摘要、事实编号和产物摘要；不传本地目录或 `bundle_path`。

接收器需要显式版本协商与幂等键。原值、条款目标、实际身份、资源身份、审核决定、发布成员分别归档，不能把 `organized.json` 直接复制成唯一科学数据库表。组织视图的坐标和识别码只用于浏览索引，不能反向充当已验证的观测身份。

## 2. 审核以事实为依据、以报告为工作单位

报告内按条款展示冻结目标与组织视图；所有行可追到独立原值及字段证据。首要操作是核对原值、主体、期间、边界、单位/分母、实际细分和条款匹配，处理同一坐标多值、缺失与冲突。

审核补充是新决定，引用原事实与证据，记录操作者、时间、原决定和新决定；不覆盖原值事实。将目标分类复制到实际维度、把资源企业视为数值主体、把缺失填零、按显示矩阵擅自合并事实，都必须拒绝。

条款的 `acceptance / evidence / output_scopes / reading` 仍是唯一声明源。审核消费者使用冻结条款，不重新编写污染物、能源或人数专属规则。自动建议与人工决定分开；`match`、范围 `covered`、任务 `completed` 都不能自动成为可发布。

## 3. 发布采用显式报告快照

发布清单绑定报告、被批准的事实/观测及条款摘要，声明排除行、未决覆盖和成员变化。发布前确认接收完整、证据可读、必需审核完成、引用摘要一致。未披露、不适用只能来自有依据的明确决定，检索未命中不算未披露。

撤下或新发布版本保留原始事实和决定血缘。继续默认 `PLATESG_AUTO_PUBLISH=0`，本轮运行不会排队交付旧 Core 导入口，也不恢复已退役包版本适配。

## 4. 数据库的职责与建议结构

建议接收模型保持以下独立实体，而非绑定提取引擎目录：

| 实体 | 主要内容 |
|---|---|
| 报告资源快照 | PDF 编号、企业、发表年、行业、散列、声明来源 |
| 提取运行快照 | 文档修订、引擎指纹、冻结条款、预算和产物摘要 |
| 来源事实 | 定量原值/定性原文、原单位、解析资料、来源锚点 |
| 实际身份与证据 | 每个主体/期间/方法/维度的原词、状态和字段证据 |
| 条款映射与覆盖 | 目标摘要、匹配关系、未完成原因 |
| 审核决定 | 对事实/身份/映射的可追溯决定，不改原事实 |
| 正式观测及来源关系 | 批准后的测量身份、值与源事实；明确区分派生值 |
| 发布清单 | 报告发布版本、成员和撤下记录 |

类型仅有定量/定性两类来源值；领域分类来自条款的独立声明。关系库可为经批准的期间、主体和维度建索引，数值使用精确十进制，原字串始终保留。新的计量/聚合能力应单独设计并保留来源血缘，不能借组织层的排序、分类、矩阵自动完成。

## 5. 建设顺序与验收

1. 先冻结交接合同、摘要验证和幂等策略；用隔离样本验证重复交接、版本不兼容、证据缺失及部分失败。不得访问现有提取输出目录。
2. 再建设审核决定和报告级查询；测试原值不改、目标/资源不能污染实际身份、修订可追溯。
3. 然后建设显式发布和独立接收器；在隔离库演练接收、撤下、恢复和重复发布，不迁移或重置现有演示库。
4. 最后接 Console，消费服务提供的状态/行动和组织定义，避免页面再算一套任务和审核状态。

正式数据库及运行中发布服务的维护须另列实施任务。本轮保留现有字典与数据库，未运行发布初始化脚本、未读取审核凭据，也未将新产物称为已审核、已发布或已入库。
