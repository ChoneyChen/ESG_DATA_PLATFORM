# 16 项基础指标快速链路（foundation16）— 2026-10-17 实施记录

## 结论

foundation16 路线已在本地完整打通：**从 PDF 到 16 项基础指标，不依赖具体报告**。

- **真实冷启动。** 三份从未处理过的报告（中国平安、一份英文报告、阿里巴巴）都从原始 PDF 跑到 16 项结论。每份 4–8 分钟，其中定向识别（OCR）占大部分；16 项提取本身 40–60 秒。
- **重新提取。** 同一份报告再次提取，复用已有结构证据和模型回答，用时约 12 秒，没有新的模型调用。
- **准确性。** 9 份报告的逐项金标准共 159 项，全部正确：0 错误、0 漏报、0 误报。
- **如实标注。** 不确定的项目保留为“待复核”“冲突”或“未找到”，不用相近概念填空。

范围没有变化：只处理平台主要指标中 E1–E3 的 16 个原编号，分属 5 个标准包：

## 链路

```
PDF
 └─ 文本层逐页打分（pypdfium2，<1 秒）→ 选出约 25 页（前言、报告期声明、高分数据页及其相邻页）
     └─ 仅对所选页 OCR（本地 PaddleOCR-VL）→ 稀疏 Document IR（保留原页码，不做 IR 复核）
         └─ 候选表格 → 表格视图（列加总关系、表头重建、页面几何标题、PDF 文本层校对）
             └─ 每表一次受约束的本地 Qwen 调用：行 → 数据点、当期列、主体口径
                 └─ 确定性绑定：原值、单位、期间、口径、概念守卫、范围 2 方法
                     └─ 正文补查（数值必须逐字出现）→ 跨来源归并（一致、冲突、分项、子口径）
                         └─ 每个标准包一个成果包 → 审核 / 导入
```

原则是**模型提议，规则裁决**：模型只决定“哪一行是哪个数据点、哪一列是当期、是否全集团口径”；数值、单位、期间和口径都由程序从原表单元格取得。每个被拒绝或降级的原因都以中文说明写进结果。

## 本轮源码变更

### 提取（`ExtractESG/extraction/src/esg_targeted/foundation/`）

| 模块 | 内容 |
|---|---|
| `tables.py` | 表格视图。新增：列加总关系（`ColumnSum`，单行精确大数也可确认）；表头错位检测与按阅读顺序重建分组表头；序号列过滤；按页面几何查找同栏标题和上方标题；单位列判定；脚注标记剥离（“8,432,549 ⁴”）。 |
| `textlayer.py`（新） | 与 PDF 原生文字层逐表核对。表格数值与文字层一致率 ≥ 80% 时，修正括注识别错字（“線電無抵扣”→“綠電抵扣”）和小数点误识（“1,274”→“1.274”）；文字层中找不到的数值标记待复核。扫描件、图片表格自动跳过。 |
| `kernel.py` | 单表请求与确定性绑定。新增：同期主体加总列切换；行名称写明的范围 2 方法优先于模型判断；被否定的方法（“instead of market-based”“而非地点法”）不算陈述；紧邻的占比行、另一方法的范围 2 行按规则补充并标为待复核；单行表以表题为主题；请求摘要（`request_sha`）。 |
| `guards.py` | 概念守卫。新增：直接 + 间接能源总量；上游、下游归入范围 3 类别；避免排放、碳抵消、净排放不算排放量；只写方法名的行（“基于市场”）取所在节标题为主题；“NO,”“SO,”下标丢失的修复；氯气、氟化物；英文子口径词边界。 |
| `consolidate.py` | 跨来源归并。新增：几个候选相加等于主值时，判为分项而非冲突；不同子口径之间不算冲突；只披露部分类别的范围 3、只有采购量的可再生电力，作为待复核候选提供；用另一方法的不同数值反推范围 2 方法（待复核）。 |
| `text_pass.py` | 正文补查。新增：同页正文唯一陈述的范围 2 方法；子口径句子标注。 |
| `engine.py` | 规划、执行、重放、汇总。新增：表格选定后的文字层核对；未找到或范围 2 方法未说明时才补查正文；按请求摘要跨会话复用回答（贪心解码，同一请求得到同一回答）；新调用与复用分开计数。 |
| `bundle.py` | 成果包写入。“未找到”缺口改为符合 `EvidenceGap` 合同的记录（`kind=not_covered`），并写入 `evidence_gap_count`。 |
| `session.py` | 会话执行器。复用同一 IR 上其他会话的成功回答，并写入本会话的调用记录，使每个会话可以独立重放。 |
| `labels.py` | 状态名改为“未找到”“未找到（有近似披露）”；新增 16 项中文定义和新的原因说明。 |
| `runner.py` | 实验命令行新增 `--reuse` / `--rerun`：只对指定的或缺少回答的表格调用模型。 |

### 定向识别（后台代理实现，本轮已复核并联调）

- `document_processing/src/esg_v2/ocr/page_selection.py`（新）：文本层页面选择器。没有文本层、可读文本过少或所选页超过 80% 时，回退为全文 OCR。
- 联调改动：
  - OCR 合同支持 `page_selection` 和 `page_indices`；
  - 只提交所选页的子 PDF；
  - 写入、读取和校验时按原页码映射；
  - 渲染、取证、融合和校验只处理已覆盖的页；
  - 定向 OCR 不会被全文请求误复用。
- 测试：`document_ir_extract/backend/tests/test_page_targeted_ocr.py`。

### 控制面与文档后端

- `model_plan.report_processing_candidates`：foundation16 请求按以下顺序选择预处理：
  1. 已有全文 IR；
  2. 已有全文 OCR，构建不复核的 IR；
  3. 只识别候选页，不复核。
- `production_automation.foundation_processing_config`：一键“提取主要指标”与批量自动化使用相同顺序，所选配置固定在条目上，恢复时重复提交同一请求。
- 合同：foundation16 必须允许有限证据（`allow_limited_evidence`）。
- `scheduler`：
  - 一次进度快照异常不再中止调度线程；
  - 启动恢复时，一个异常任务不再阻止后端启动。

  这两个故障都在本轮真实运行中出现过。
- `progress`：表格进度单位改为合同允许的 `objects`。原来的 `source_tables` 曾导致调度线程崩溃。
- 列表性能：`GET /api/report-sessions?view=summary` 返回精简行；报告聚合内嵌的会话改用同一精简投影。会话列表从 6.5 MB 降到 70 KB（0.9 秒），报告聚合从 7.9 MB 降到 456 KB。
- `GET /api/report-sessions/{id}/foundation16`：由文档后端解析平台会话编号后转发。此前看板用平台编号直接请求提取后端，返回 404。

## 未完成与风险

1. **提取后端既有测试失败（15 项，本轮之前即存在）。**
   - 未纳入版本控制的 `evidence/disclosure.py` 把智能体版本升到了 v9，测试仍期望 v8；
   - `DELETE /api/jobs/{id}` 返回 422，测试期望 409；
   - 3 项预算语义测试与当前“各包独立预算”实现不一致。
2. **OCR 成本。** 冷启动的大部分时间花在 OCR（25 页约 3–6 分钟，数据密集页较慢）。扫描版 PDF（没有文本层）会回退为全文 OCR，本轮没有用真实扫描件测试。
3. **旧会话不会自动更新。** 已完成会话保留当时的结论；重新提取同一报告约 12 秒即可应用最新规则。
4. **金标准需要复核。** 7 份报告的金标准由本轮整理，需要业务方复核。
5. **入库链路本轮未重复验证。** 本轮没有向真实 PlatESG 数据库交付；此前只在临时库验证过。临时 PlatESG（8766 端口）已由用户停止。
6. **工程整理。** 没有对 ConsoleESG 做全量格式化：工作区有大量未提交的用户改动，统一格式化会把这些改动淹没在差异中，宜在提交后单独进行。
7. **未提交。** 本轮所有改动都没有提交，也没有推送。
