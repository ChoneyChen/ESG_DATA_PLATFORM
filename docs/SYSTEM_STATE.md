# 系统状态（2026-10-28）

当前事实的唯一状态快照，随每轮更新覆盖，不再按日期堆积副本。变化过程见[更新日志](CHANGELOG.md)，
项目范围与使用方式见[根 README](../README.md)。

## 1. 服务

| 服务 | 地址 | 启动 |
|---|---|---|
| 操作台（静态） | http://127.0.0.1:18081/ | `ExtractESG/scripts/start_local_workbenches.sh` |
| Document API | http://127.0.0.1:18080/docs | 同上 |
| Targeted API | http://127.0.0.1:18180/api/docs | 同上 |
| 数据平台 / 公开站 | http://127.0.0.1:8765/ | `PlatESG/scripts/run.sh` |

操作台通过同源 `/document`、`/targeted`、`/publication` 代理访问三个后端。读取不是独立步骤：
工作台只有「报告 → 提取 → 审核 → 发布」，页面读取与结构证据构建在提取内部完成。

操作台（ConsoleESG）是**唯一的人工界面**。ExtractESG 自带的旧前端（`document_ir_extract/frontend`，
原 `/legacy/` 入口）已于 2026-10-23 移除，其功能由操作台覆盖；`ExtractESG` 现在只提供 HTTP API 与命令行。

公开站（`PlatESG/frontend`）默认是产品介绍页；进入平台后为概览、企业、指标、同行比较、报告来源、
数据复核与 API 文档七个页面，只读取固定发布版本，不接触提取目录、候选或审核人。

## 2. 本机身份

本机回环且不带凭据的请求由数据平台识别为 `local-operator`（读取、审核、发布、管理）；
带凭据的请求仍按 `PLATESG_OPERATORS_JSON` 验证，非本机无凭据请求拒绝。下游服务收到本机无凭据请求时
不带凭据向数据平台确认身份。`PLATESG_LOCAL_OPERATOR=0` 关闭本机识别，此后所有请求都需要凭据。
风险：本机任何进程都能以该身份调用写接口，多人共用机器时应关闭。

实体与报告登记；清理前目录备份在 `PlatESG/.local/backups/`。2026-10-24 已清空：产物 0 条，
链路 657 条（含字典 1.4.5），公开站为数据集 0 的空库。2026-10-25 重新跑通批量链路：
5 份报告各 16 个条款任务全部完成并交付候选，共 198 条条款映射候选。第四十轮发现其中 98 条是同一报告
被读取两次产生的重复事实；交付层已按“报告 + 条款 + 单元格 + 值 + 期间 + 边界”复用已有 disclosure，
并增加自动审核前的历史重复折叠。不同范围、不同污染物类别、不同年份是不同的单元格/期间，全部保留。
`machine-verification-v3` 重跑后曾达到 157 条候选、140 条已批准、17 条待人工。

第四十一轮把发布改为**报告级**：每份报告独立记录 `draft / pending / published / withdrawn / deleted`
与 `publication_version`；公开读取只取当前已发布报告版本中的 observation 成员。全局 `dataset_versions`
仅作旧链接兼容快照，不再是控制台发布入口。真实库已验证：发布 A 只增加 A 的观测，撤下 A 立即从公开站消失，
B 不受影响。

按用户要求，2026-10-25 随后清空全部报告产物：移除 4,274 行产物，链路 678 行保持不变，保留 6 个报告身份
与 18 个实体。当前为数据集 0、**0 候选、0 公开观测、6 份报告均为 draft**，供从头测试。历史候选质量结论
保留在[更新日志](CHANGELOG.md)第四十轮。

单报告候选层可在报告详情“审核”页定位与删除：`GET /internal/v1/report-artifacts` 列出候选、mapping/disclosure、
IR/OCR 来源、页码、导入批次 `bundle_ref` 与 PDF 资产；`POST /internal/v1/report-artifacts/delete` 只删除
未发布、未保存口径、非项目延伸、未被后续披露引用的候选。`POST /internal/v1/report-artifacts/delete-report`
可删除整份报告产物：未受保护候选物理删除，已保存口径与不可变快照保留审计，公开数据撤下。
报告发布控制走 `GET /internal/v1/report-publications` 与 `publish / withdraw / delete` 三个报告级动作；
公开读取只取当前已发布报告版本的 observation 成员。提取成果目录由提取服务的任务记录删除负责；
彻底物理清理仍使用全库 `artifact-purge`（已包含报告发布表）。

提取结束到候选审核是自动的：提取服务在报告终止时立即 materialize 内容寻址成果包；
`POST /api/console/report-sessions/{id}/handoff` 一次完成“保存成果 → 解析该 PDF 已登记的报告身份 →
交付 → 自动审核”。`PipelinePlanCoordinator` 在报告计划进入终态后自行调用同一衔接，浏览器关闭也执行；
仍归批量生产所有的计划标记 `deferred`，由批量交付步负责。衔接失败按 30 秒 / 5 分钟退避，12 次后停止，
状态写入计划文档的 `auto_handoff`（页面据此显示，不依赖本次会话的浏览器内存）。

## 6. 本轮修复的链路缺陷

| 缺陷 | 通用规则 |
|---|---|
| 「核定的年度排放总量」被当成实际排放的冲突值 | 许可、配额、核定上限属于另一类量，不参与实际值归并 |
| 叙述句中「较上年增加…」把数值判成变化量 | 概念判定看数值所在短句及其前一分句，不整句判断 |
| 模型把「257万立方米」拆成值「257 万」+ 单位「立方米」 | 值与单位分离，按段落实际印刷的单位归一 |
| 结论只保存 code/status | 成果包保留成员、原值、单位、拒因与候选 |
| OCR/IR 列表返回空删除请求体 | 列表宣告的删除身份必须与 DELETE 校验的一致 |
| 删除身份按被修改的计划计算 | 删除身份一律从存储状态重新计算 |
| 共享 pin 文件在批量删除中消失导致 409 | 删除身份不含记账用 pin；快照容忍已删除路径 |
| 计划缺少 `revision` 时删除永远冲突 | 删除动作读取存储状态的最新修订 |
| 短暂的依赖不可用把会话判死，且列表无继续入口 | 列表直接给出“继续执行”，写出停止原因；成果标记规则版本，旧规则结果需重跑 |
| 每行都发一次数据库状态查询并显示“待核对” | 未交付的会话只显示“未交付”，不发起查询 |
| 读取选页只认环境指标，社会/治理页不被读取 | 每个指标族先保底选页，再由总分补足；读写词表一致性测试锁定 |
| 会话列表每次轮询都重读全部阶段文件 | 列表结果缓存 5 秒，状态变更时失效 |
| 计数单位被“不是数量”规则误杀 | 只有与指标声明维度不同的计数/货币单位才拒绝 |
| 运营范围（operational control）总量被当成冲突 | 不同合并边界记为另一视图，不参与冲突比较 |
| 模型漏答的表格行直接丢失 | 行标签与单位通过条款守卫即作为候选，交同一套守卫裁决 |
| 其它族的表格里的同一概念永远看不到（污染物表里的排水总量） | 行级恢复跨族扫描，行的标签自己成立就作为候选 |
| 同一指标在集团/基地/子公司/地区多个范围下的值互相压制或只作展示 | 按范围拆成独立视图与独立事实，各自带边界发布 |
| 模型对某张表返回空列时整张表被丢弃 | 按表头年份或末列确定取值列，行仍交守卫裁决 |
| 强度单位被当成绝对量；括号换算说明被当成强度 | 按分母识别强度维度，括号内说明不改变主单位 |
| 两栏表格把单位格当标签 | 标签是单位、单位是标签时按内容纠正 |
| GRI/ESRS 索引行、地区行、废弃物品类被当成总量 | 索引、地区、品类按非数据或部分处理 |
| 覆盖率被当成事故率 | 覆盖率与比率分开判定 |
| 慢请求被下一轮轮询反复中止，界面永远“正在读取” | 每个资源只允许一个在途请求；失败按 5 秒自恢复，迟到响应按资源键丢弃 |
| 新打开的工作台重放队列全部历史事件，把后端 CPU 打满 | 事件流支持 `latest`，空闲流只做一次主键查询；页面隐藏时断开、恢复时重连 |
| 每次读取会话列表都重新解析全部计划 | 计划解析结果缓存 2 秒，写计划即失效 |
| 发布口径要求人工选择指标定义已固定的维度 | 按 `fixed_dimensions` 预填，操作员不再为固定值做选择 |
| 吨标准煤等常见能源单位无法换算 | 单位规则 1.3.0 增加标准煤/标准油/万吉焦/太焦，换算保留原始值与依据 |
| 水体以质量（吨）披露时无法与体积口径比较 | 单位规则 1.5.0 按水的单位密度 1:1 折算，原值与印刷单位不变 |
| 处理失败的 PDF 在没有读取版本时被显示成“未提取” | 失败状态先于空版本判断，筛选与提示都能看到失败 |

## 7. 已知问题

- 发布服务（8765）默认 `PLATESG_AUTO_PUBLISH=1`，重启会立即处理待发布事件。人工发布模式必须用
  `PLATESG_AUTO_PUBLISH=0` 启动；第四十一轮已改为报告级发布，当前服务仍以人工模式运行。
- 发布服务重启后，工作台的交付会先收到 `runtime_requires_restart`（发布服务判定工作台版本已过期）；
  重新启动发布服务即可恢复，自动衔接会按退避自动重试，不需要重新点交付。
- 2026-10-25 第四十一轮已清空全部报告产物：当前 0 候选、0 公开观测、6 份报告均为 `draft`。
  发布、撤下、删除都要在报告级控制台逐份执行；不存在全平台“一次发布所有报告”的入口。
- 三个工作台服务由同一个启动脚本托管：杀掉其中一个，看门狗会判定异常并停止其余两个。
  需要重启就整体重来，不要单独 kill 一个后端。
- 发布服务（8765）与工作台共用同一套发布指纹协议，但它不在启动脚本内；改动发布后端后要单独重启，
  否则交付会返回 `runtime_requires_restart`。各服务只为自身代码重启，跨服务只校验共享标准与目录合同。
- 公开发布站的历史观测已随第四十一轮清理移除；从头测试时，重新提取、审核后按报告发布即可恢复。
  报告身份（6 份）与实体（18 个）保留，不需重建链路。
- 本地 CrawlESG 只有索引，没有本链路可读的 PDF；索引记录不替代 PDF、报告 ID 或主体登记。
  `pdf_available=false`，PDF 交接接口预留；“导入 PDF”按钮保持禁用，直到 Crawl 提供 PDF 路径与 SHA-256。
  ESEF ZIP 不作为 PDF 资产，也不在本链路解析。
- Crawl 源页面只做索引元数据与 PDF 接口预留，不提供 ESEF 事实读取、Crawl 运行控制或自动采集派发。
- 单报告候选删除是逻辑候选层删除，不是物理全库清理：导入批次审计、不可变来源快照与报告身份保留；
  已发布或已保存口径的候选会拒绝删除。需要彻底清空时使用全库 `artifact-purge`。
- 报告身份现含外部索引字段，但这些字段只是来源记录；`publisher_entity_ref` 仍必须显式选择已登记主体。

- `report-fact-agent` / `report-semantics` 版本常量已收敛为单一来源，测试直接引用常量；此前的 16 项失败已清零。
- 99 个包均已撰写中文标签与正向定义；其中 48 个原机械生成包于 2.3.0 完成 509 条，但仍需真实报告验收与业务批准。
- 平台字典为 1.4.5；字典、单位规则与发布版本一经登记不可修改，内容变化必须另起版本。
- 页面读取仍以本地视觉模型为兜底，冷启动耗时主要在读取阶段。
- 香港中华煤气 E1-5_01 在正文表（6,442,175 GJ）与附录统计表（7,999,444 GJ）给出两个“总能耗”，
  两表口径不同但标题相同；链路如实保留为冲突并附页码，待人工判断，不自动择一。
- 重点条款 32 条现已全部就绪；此前按旧包版本（2.1.1）交付的会话，其冻结标准快照与新包 2.2.0
  不一致，发布会给出 `standard_snapshot_mismatch`，需要按新包重新提取后交付（这是不可变版本的预期行为）。
- 新就绪条款的真实运行：2.3.0 包可正常加载和阅读原文，但报告未披露对应内容时，规划器会在重复查询后
  停止并把 gap 记为 `planner_stalled`；证据不足的映射结论同时保留。链路不编造事实，归类仍待优化。
- 只有分项、没有主值的定量条款（`child_only`）：子表保留在提取证据与操作台；平台需要主值确认后才生成观测，
  不会用分项之和冒充主值。
- 水体按质量披露时按单位密度折算（1.5.4 引入，现行规则 1.5.6）。若原文的“吨”并非水当量（例如以干重计的悬浮物），
  需要人工在口径里改用对应单位，链路不会自动猜。
- 单位规则与字典快照一经登记不可修改（数据库按摘要校验），内容变化必须另起版本；
  单位规则因此从 1.5.0 走到现行 1.5.6、字典从 1.4.0 走到 1.4.3。
- 报告期若只有文件名或表头年份作依据，交付面板会标注“证据偏弱”，需人工对照封面确认。
- 同一指标在同一页可能有两个边界（宁德时代在第 72 页披露电池生产基地总量、第 73 页披露集团总量，
  数值相差约 67 倍）。链路读取所选测量主体对应的表；测量边界必须由人工在口径里确认，不能默认。
