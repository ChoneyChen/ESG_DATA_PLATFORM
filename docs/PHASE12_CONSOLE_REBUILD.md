## 1. 这一轮改了什么

阶段 6 已经建立了唯一 `ReportRun` 投影，本轮把它落到每个页面的信息层级上：

| 页面 | 之前 | 现在 |
|---|---|---|
| 报告库 | 六轴（阶段 6） | 保持；概览条与库页计数一致 |

| 发布库 | 6 个 tab（按报告/阻塞/收据/已发布/事件/覆盖） | **4 个 tab**：待发布 / 发布条件与阻塞 / 已发布与修订 / 记录与诊断 |

| 条款中心 | 只读 + 验收 | 增加条款编辑器与草稿（阶段 11） |

## 2. 审核按原因分组

`groupReviewCandidates` 用候选自带的 `reason_codes` 归类，优先级从硬到软：

```text
数值与来源冲突 → 单位与分母 → 主体、期间与边界 → 条款映射 → 事实与证据 → 其他
```

两条规则保证分组说真话：

- `publication_not_evaluated` **不是**审核原因（只是发布门禁还没跑），不能用来掩盖真正缺失的步骤；
- 没有原因码时，按**尚未完成的审核步骤**归类（事实未批 / 映射未批 / 口径未填），而不是一律丢进“其他”。

真实核对：中国石化 5 条待审候选原本全部落在“其他”，修正后归入“事实与证据”。

## 3. 发布库收敛

- 待发布：可发布报告卡 + 发布/撤下/删除 + 成员明细；
- 发布条件与阻塞：报告卡 + 自动审核建议 + 阻塞原因；
- 已发布与修订：已发布条款、来源、修订入口；
- 记录与诊断：交付收据（可重试）、持久发布事件、覆盖决定。

收据、事件、覆盖本质是诊断与补录，不再与日常发布并列。

## 4. 运行中心

执行队列、模型与资源、存储引用保持；新增“技术诊断入口”，明确页面读取、结构证据与逐对象修复
从报告详情 / 报告处理进入，工具区不再把它们当作生产主线目的地。

## 7. 仍然存在的边界

- 单份与批量仍落在两个后端能力上（报告会话 / 生产计划），Console 入口已统一，但未合并为一个请求对象。
- 审核页仍是候选表格，只是按原因分组；没有做“逐条向导式核对”。
- 提取详情的阶段与运行仍是 tab，不是右侧抽屉；技术信息与业务信息仍在同一页面，只是分区。
- 发布库没有“成员变化对比”（只显示当前成员）。
