# 阶段 6：Console 统一报告状态与产物投影

日期：2026-10-28  
范围：`ConsoleESG`（Plat 前端不在本轮范围）。  
原则：Console 围绕业务对象组织，不围绕技术模块组织；页面不各自拼一套状态。

## 1. 修复的状态分裂

改造前，同一份报告在不同页面有不同说法：

| 位置 | 只看 | 结果 |
|---|---|---|
| 报告库 | `processing_status` 与 OCR/IR 版本 | 只能表达“未读取 / 已读取” |
| 报告详情 | 资产、处理、会话、候选、发布各自组合 | 统计口径与库页不一致 |
| 运行监视 | 按任务标题临时分组 | 一份报告的准备、提取被拆成多张卡 |
| 审核 / 发布 | 候选 + 报告状态再次组合 | 与库页的“待审核”数不同 |

根因不是样式，而是**没有一份统一的报告状态与产物投影**。

## 2. 统一投影

`ConsoleESG/src/reportRun.ts` 定义唯一的 `ReportRun`，六条互相独立的轴：

```text
identity · evidence · extraction · handoff · review · publication
```

| 轴 | 取值 | 来源 |
|---|---|---|
| identity | `complete` / `incomplete` + 缺失字段 | 报告库 `report_metadata` |
| evidence | `none` / `running` / `failed` / `ready` | 处理状态与 OCR/IR 版本 |
| extraction | `none` / `queued` / `running` / `ready` / `failed` | 报告会话摘要 |
| handoff | `not_started` / `pending` / `delivered` / `failed` | 会话 `database_status` |
| review | `none` / `review` / `ready` / `blocked` + 候选/待审/已审/阻塞数 | 报告发布记录 |
| publication | `draft` / `published` / `withdrawn` / `deleted` + 版本与观测数 | 报告发布记录 |

`useReportRuns()` 是三处权威的**唯一**装配点：文档服务（身份、证据、提取）、发布服务（审核、发布）、
执行队列（进行中的任务）。报告库、运行监视、报告详情都读同一份结果。

**身份不阻断读取与提取**：没有登记报告身份时仍可提取，但交付与发布要求身份完整——
否则无法成为可追溯的公开来源。这是本轮明确的行为取舍。

每份报告只给**一个主行动**，按最早未完成的一步决定：

```text
读取进度 → 重新提取 → 提取指标 → 提取成果 → 补身份（仅当阻断交付/发布）
→ 处理发布阻塞 → 交付并审核 → 审核（N）→ 发布该报告 → 查看发布
```

## 3. 页面变化

- **报告库**：每行显示六段阶段标记（身份／证据／提取／交付／审核／发布），
  主按钮来自投影的 `next_action`，不再由页面自行判断“下一步”。
  概览条改为：全部、待补身份、待提取、待审核、待发布、已发布、有问题。
- **报告详情**：概览与各 tab 顶部都显示同一组阶段标记和当前主行动。
- **运行监视**：以**报告**为单位聚合进行中任务，显示同一组阶段标记、当前内部步骤与取消操作；
  无法归属到报告的队列任务单独列出，不强行归并。
- **导航**：工具区收敛为“批量生产 / 标准中心 / 运行中心”。页面读取与结构证据修复不再占生产主线入口，
  从运行中心或报告详情进入（`/processing`、`/ocr` 路由保留）。
- **读取共享**：同一投影在库页与侧栏同时挂载时会重复请求，新增 1.2 秒的共享读缓存
  （`readCached`），身份变化即清空；测试模式下关闭，保证测试仍按真实请求断言。

## 4. 真实运行核对（2026-10-28）

真实报告库与发布库（18 份报告，`.local/data` 正式库，未做任何写入）：

| 视图 | 结果 |
|---|---|
| 报告库概览 | 全部 18 · 待补身份 0 · 待提取 11 · 待审核 2 · 待发布 1 · 已发布 0 · 有问题 2 |
| 中国石化详情 | 身份 ✓ 证据 ✓ 提取 ✓ 交付 ✓ 审核（当前）发布（未开始）；主行动“审核（5）” |
| 发布页 | 待发布报告 1 · 已发布 0 · 有阻塞报告 2 |

库页、详情页与发布页的“待发布 / 有问题”数量一致，说明三处读的是同一份投影，
而不是各自维护的计数。

## 5. 测试

| 套件 | 结果 |
|---|---|
| ConsoleESG | 240 通过（新增 12 条投影测试：六轴取值、主行动顺序、任务归属、阶段标记） |
| 其余后端 | 本轮未改动，沿用阶段 5 的结果 |

投影测试覆盖了容易被写错的判断：身份不阻断提取但阻断交付、未交付成果不等于“0 条候选”、
有阻塞时不给“审核”而是“处理阻塞”、已发布报告保留版本号、无法归属的任务不并入任意报告。

## 6. 已知边界

- 单份与批量的创建仍落在两个后端能力上：单份走报告会话，多份走生产计划；Console 侧入口已统一
  （报告库多选＝批量，向导多选＝逐份会话），但不合并为一个后端请求对象。
- 审核与发布页仍以发布服务的候选与报告发布记录为权威计数；它们与投影的审核/发布轴同源，
  但没有把候选明细并入投影对象。
- 共享读缓存只作用于 GET 资源，且不缓存写操作；平台服务不可用时仍按原有退避重试。
- 阶段标记表达的是报告当前所处阶段，不代表质量结论；条款级的可发布状态见阶段 5 的条款中心。
