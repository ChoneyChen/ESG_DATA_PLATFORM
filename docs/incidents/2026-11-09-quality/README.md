# 批量提取的效率、质量与阅读边界

原50份批次保持停止。本轮从实际状态、调用、证据和产物定位问题，修改所属模块，再用独立目录中的真实PDF任务观察结果。当前引擎为 `clause-backbone-2.7`。

## 查明的原因

原批次为49份取消、1份部分结束：774次调用只完成53条阅读；1777条原值中49条标为目标。原值数与目标数不是准确率。服务停止后还留下18个排队子任务。

部分结束的First Solar只执行3次模型调用，随后出现34条文档连接错误，汇总却显示处理32条。其能源总量还被两处错误阻碍：`ratio`误匹配`Operational`，行标签里明示的`MWh`没有绑定为单位。

完整实跑进一步暴露出一条成本放大链：

> `million liters`、`Headcount`等单位未正确识别 → 已找到的值被标成未决 → 继续扩围 → 新增无关候选 → 逐批补读属性；全局上下文摘要变化又让部分事实重新补读。

此外，整体长名称检索漏掉短表名，补页后的相同物理内容重复阅读，模型反复生成属性与理由。定性表格输入还混入数值网格、缺少直接对应的原文引用；供应商筛选清单中的话题短语被误当成实际污染测量方法。

收紧阅读后实跑发现，正确水量表还被排在第5、第6位：旧检索对整张混合指标表评分，其他行的取水、耗水词也处罚回用水/排水目标行。有限候选额度因此先用在了错误对象上。问题在证据排序，不能用扩大额度解决。

## 按模块收敛

| 模块 | 当前职责与修复 | 主要文件 |
|---|---|---|
| 独立条款 | 定义、词典、范围、排除与阅读规则仍归单条合同；检索通过`vocabulary_refs`引用本条词典。修正英文词边界，以及污染测量方法与供应商准则清单的边界。 | `ClauseESG/clauses/`、`contract.py`、`search.py`、`reading.py` |
| 共享数据层 | 一处识别印刷单位表达式，文档和绑定器共同消费；支持缩放单位、人数、时长及英文温室气体单位。原单位和原值保留，提取不暗中换算。 | `esg_data/units.py`、`quantities.py` |
| 文档证据 | 从行标签、列头和正文绑定实际单位；日期、型号和标准引用不是量值。定量表按最佳局部行及共享表头评分，负向词只处罚该行；单位种类偏好来自条款搜索计划。页定位消费条款计划，额外页数由提取请求传递；可搜索PDF不因无关键词退回整本OCR。 | `document/physical.py`、`literals.py`、`search_ranking.py`、`evidence_service.py`、`api/evidence.py` |
| 候选与两类阅读 | 通用词项检索处理括号和英文词形；按条款既有条件筛选候选。定量只选行列，定性直接选择原文引用；不让模型输出量值。 | `retrieval.py`、`selection.py`、`reading_frame.py`、`decisions.py` |
| 阅读策略与进度 | 集中管理命中对象、候选数量、补页和补读限额；续跑保留所选对象及已尝试属性。主循环不再为可选属性反复请求新页。 | `reading_policy.py`、`engine.py` |
| 绑定与属性补充 | 明示量值、原单位、所有列示年份由物理证据绑定；未知单位类别不再把目标降为未决。定性判断使用所选引句和直接关联的行列标题，不借原单元格中未选的其他句子；完整原文保留供查阅。只给已命中事实补属性，同一事实的同一属性只尝试一次。 | `binding.py`、`reading_frame.py`、`period_binding.py`、`enrichment.py` |
| 运行与Console后端 | 文档断连保留检查点并中断，完成数按真实检查点计算；错误传到报告级状态。取消同时停止阅读与准备，启动前处理已取消任务的遗留子任务。 | `runtime.py`、`pipeline/extraction.py`、`ConsoleESG/backend/.../application.py` |
| 独立输出 | 原值仍为`quantitative`与`assertion`，导出包按共享合同准备；缺少可选属性不阻止保存原值。 | `esg_contracts/`、`exporting.py` |

模型理解不跨条款复用。同一任务内的物理证据去重和续跑进度，用于避免重复工作。条款集合仍只是独立条款ID的选择，没有另建“32条提取器”。

## 默认阅读边界

[主提取模块说明](../../../ExtractESG/extraction/README.md)与`reading_policy.py`是当前执行说明；每次运行保存`input/reading-policy.json`。

| 行为 | 默认边界 |
|---|---|
| 集中目标数据 | 命中一个物理对象后，完成其全部分段、行列和历史年份，停止向其他对象扩展 |
| 未命中候选 | 每来源最多4个主候选、4个词项候选 |
| 单条款补页 | 最多1轮，最多4个新页 |
| 全报告补页 | 额外定位最多8个新页；已准备相邻页可供续表使用 |
| 可选属性 | 仅已命中事实、仅已准备证据，每条款最多2次模型调用 |
| 继续执行 | 未知属性保持未知；局部边界随检查点保存，不因轮转重置 |

不再为收齐可选属性启动OCR。完成表示完成这套有界流程，不能解释为穷举全报告或证明未披露。请求的128次调用、100个对象/条款、4096输出tokens和4小时总预算没有增大。

## 真实任务观察

两份原PDF：First Solar 2026、协鑫科技2023。2.4、2.5均使用原32条选择；2.6协鑫重跑完整32条，First Solar重跑涉及能源、范围一排放、回用水和定性方法的4条。没有手写结果、改写旧任务或用模拟数据代替提取。

2.4的两份任务均完成32/32并准备导出：First Solar为49次调用、38条原值；协鑫为75次调用、76条原值。但该轮仍有已确认缺陷：人数、水量因单位提示变成未决；First Solar有一条供应商筛选主题误命中。因此这组数据作为修复前对照。

2.5两份均完成32/32，调用从49、75降至27、20。但18个核心值仅13个正确产出：漏掉First Solar两年回用水和协鑫三年排水。该轮只证明成本下降，不能作为质量通过结论；2.6已改用行级排序，两张正确表在服务端实际查询中均升至首位，没有放宽候选或补页额度。

2.6两份均完成，18个核心值的值、年份、原单位和目标关系全部对应。其中协鑫完整32条使用23次调用、49条原值，提取工作进程累计活动472.400秒；2.4对照为75次、1658.987秒。First Solar的4条使用7次调用、8条原值，累计活动74.453秒。后者是局部复跑，不代表完整32条的最终吞吐。

这轮还发现协鑫的产品碳足迹测量被误归入污染方法：所选引句之外，原单元格另一句的`lead`被当成污染物铅，补足了不该补足的条款语义。2.7收紧通用引用边界，协鑫从PDF入口复跑1次调用后，这句为`different`，不再是目标。没有向主干加入公司特殊条件。

宁德时代正例复跑又发现条款内容没有声明通用废水、废气介质词，导致实际自行监测说明被排除。补充只写入独立`E2-4_09`合同，最终从PDF入口完成3次调用：实际自行监测方案为`match`，供应商审核陈述为`uncertain`；此前复跑还正确保留了土壤、地下水调查与自行监测原句。旧冻结任务按原合同保留。

| 此前遗漏的数据 | 最终实际产出 | 原单位 |
|---|---|---|
| First Solar回用水 | 2024：469；2025：510 | `million liters` |
| 协鑫排水 | 2021：459；2022：837；2023：933 | `Ten thousand tonnes` |
| 协鑫员工人数原先被降为未决 | 2021：8863；2022：11527；2023：15002 | `Headcount` |

18项还覆盖能源、范围一温室气体和危废，均按值、年份、原单位和目标关系对照原PDF。实际运行与逐值结果保存在[runtime.json](runtime.json)。2.6的49条原值不等于49条已证明准确；其已知定性误判由上述2.7专项复跑处理，未暗改旧产物。

这些任务可以复用文档模块已有的物理OCR/IR准备结果，没有复用跨条款的模型理解。因此耗时是当前任务观察，不能当作冷启动OCR或50份整批吞吐基准。

同一能源表的主阅读，原任务3219输出tokens、225.981秒；2.4为56 tokens、18.543秒。属性补读另计，这不是整批提速倍数。期间主机曾在19:28合盖休眠、约21:24恢复；该时段不计作模型吞吐表现。

最终实跑均无执行错误，导出包为`prepared`。2.6实测每条款属性调用最多1次、补页最多1轮，协鑫新增8页、First Solar新增4页；2.7定性复跑分别新增4、0、0页。前端共享类型已生成，生产构建通过；没有新增单元测试套件或将模拟结果作为完成依据。

## 原批次与实际边界

18个遗留子任务已经通过正式取消流程停止，主调度器未启动。原50份仍为49份取消、1份部分结束，1777条原值保留；与轮前记录核对的49份请求和冻结目标摘要均未变，1590个已记录事实ID全部保留。测试结束后隔离服务也已停止，没有接收入库或发布。

本轮验证范围是这些真实报告与所选条款，不能据此给出全库准确率。协鑫第18页的政策表存在IR过度分列；本轮不把无关碎片作为目标方法，文字重建本身仍有局限。局部数据未找到时保留未确认状态，不启动无限补读。
