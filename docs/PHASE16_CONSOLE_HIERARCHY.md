# 阶段 16：Console 层级化重制（标准中心、发布）

日期：2026-10-28
范围：ConsoleESG 标准中心、发布页、导航与样式；标准包简述名；条款存储形态核对。

## 1. 标准到底怎么存

一句话：**包是发布边界，条款是编辑与验收边界，两者都是目录，不是数据库行。**

| 层 | 位置 | 形态 |
|---|---|---|
| 作者源 | `ExtractESG/standards/authoring/esrs/2023-set1/<pkg>/<ver>/` | 可编辑源（不可变版本） |
| 编译包 | `releases/<package_id>/<version>/package.json` | 一个包一个文件，登记在 `registry/releases.json`，带源摘要与校验和 |
| 当前版本 | `registry/esrs/2023-set1/registry.json` | 每包一条 pin（版本 + 运行时路径 + 摘要） |
| 条款 | `clauses/<package_id>/<version>/<原编号>/` | **每条五个文件**：`clause / retrieval / evidence / acceptance / provenance` |
| 条款索引 | `clauses/catalog.json` | 包 → 条款路径与合同摘要 |
| 固定口径 | `profiles/esrs/2023-set1/clause-fixed-axes.json` | 字典与条款目录共读一份 |
| 包简述名 | `profiles/esrs/2023-set1/package-titles.json` | 前端目录显示用，不改变包合同 |

现状：99 个当前包（e1-5 另有 2.1.2 试点版本，合计 100 个已登记版本）、1,147 条条款目录，
`build_clause_catalog.py --check` 0 stale。每个包独立出版本、独立摘要；包内条款独立成目录、
格式统一，改一条条款只动一个目录。

## 2. 标准中心：目录 → 包 → 条款

旧页面是「左侧列表 + 右侧一大块合同」，所有内容堆在一屏。现在改成三级子页面：

```text
#/standards                         目录（按业务概念/层级/成熟度/依赖分组）
#/standards/<package_id>            包内条款列表（每条一行：编号、名称、角色、状态）
#/standards/<package_id>/<SID>      条款详情（定义、边界、易混、口径、检索与证据、验收、关系）
```

- 每一级都有返回按钮：条款页返回该包，包页返回标准中心。
- 目录行显示**简述名**（如 `E1-5 能源消耗`），条款行显示**条款名**（如 `E1-5_05 可再生能源消费总量`）。
- 包页与条款页的标题都带编号角标；包页显示 `v2.1.3 · 23 条条款 · 已验收 1`。
- 「新增条款」是独立弹窗：选条款、写修改说明、创建草稿；创建后直接在编辑弹窗打开，
  不离开当前页面。条款页的「编辑条款」进入同一弹窗。
- 目录仍只显示当前版本；项目延伸条款收进底部折叠，不再占据主视图。
- 长文本（完整合同 JSON）只在「完整合同」诊断折叠中出现。

## 3. 发布：报告列表 → 报告页

旧的「待发布」在报告卡里内嵌可展开的候选长列表，一展开就是一大串。现在：

```text
#/publication             报告列表（待发布 / 阻塞 / 已发布 / 诊断四个视图）
#/publication/<report>    单份报告：候选表格 + 发布/撤下/删除 + 机器核验折叠
```

候选表格一行一条：条款、原值、事实/映射/发布状态、阻塞原因、审核入口。
报告级操作与状态徽标只在报告页出现；列表页只保留「查看候选 · N」入口。
