# 工作台读取500：2026-10-12修复记录

## 故障与因果

用户进入工作台后遇到“服务返回非JSON响应（500）”。现场直接请求确认：Document API的提取会话列表和准备阶段任务详情返回500、`text/plain`；处理列表、报告资产、队列正常。日志指向 `_report_plan_detail` 读取 `document['ir_run_id']` 的KeyError。

准备阶段尚无固定IR，但原动作生成逻辑仍扫描全部IR，并比较 `candidate.parent_ir_run_id == document.get('ir_run_id')`。两端都是空值时，把一个根IR误认成当前任务的修复子版本；随后构造切换动作时访问不存在的当前IR字段。一条合法的未完成准备任务因此阻断整个会话列表，以及聚合它的报告目录。读取异常未按API错误合同封装，静态代理如实转发了非JSON的500。

这不是报告数据损坏的证据，也不是OCR必须删除或跳过。上一轮冒烟验证了服务、路由和空自动化列表，未覆盖“准备阶段未生成IR＋库中已有根IR”的读取组合；合成前端fixture还把真实报告目录`items`错误模拟成`reports`。

## 修复

- 将证据动作投影移到独立只读模块；没有明确当前IR时不扫描、不产生修复或切换动作，但任务、准备状态、取消和生命周期入口正常显示。
- 修复候选必须具有真实当前父ID、匹配目录／manifest身份、明确可用性及相同PDF和声明的lineage；原执行端继续验证证据完整性和变更范围，不用读取建议代替执行权限。扫描有明确规模限制。
- 无固定IR时直接请求证据切换返回409，不访问空身份或派发任务。切换后会恢复提取的动作如实标记可能调用模型。
- Document API未捕获异常返回JSON500，附问题编号供日志关联；不返回堆栈、请求体或凭据，也不把未知写操作结果宣称为安全可重试。
- 前端错误包含服务、接口、HTTP状态和可用问题编号；不泄露响应原文、查询参数或密钥。非JSON的2xx同样不能伪装为成功数据。
- 自动生产报告选择改用真实`console-report-v1.items`，修正已登记报告显示为空的合同错误。读取失败提示改为“本次未取得最新状态”，不无依据宣称数据保存成功。
