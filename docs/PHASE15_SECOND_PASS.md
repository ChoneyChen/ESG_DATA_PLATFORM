# 第二轮全量核对：按《全链路检查报告与升级规划》逐条落实

日期：2026-10-28
范围：条款科学合同、条款目录、公开数据产品、标准中心、Console 与旧版本清理。

本轮对报告的每一节重新核对：已满足的给出证据，未满足的落到代码，仍不成立的写清边界。

## 0. 执行摘要

报告的三个核心决策——统一条款科学合同、统一中立事实主干、统一报告状态投影——本轮补齐了
此前最实质的两个缺口：

1. **固定口径只有一份**：条款的固定维度（如 `E1-5_05` 固定为可再生）原先写在平台构建脚本里，
   条款目录从未真正读到它（构建脚本的字典路径默认指向不存在的目录，`publication.fixed_axes` 一直是空）。
   现在固定口径声明在标准侧 `profiles/esrs/2023-set1/clause-fixed-axes.json`，
   平台字典与条款目录都只读这一处；1,147 条条款目录重建后，31 条有固定口径的条款第一次真正携带它。
2. **证据来源分层公开**：公开观测新增 `context_sources`（每个口径字段的证据层级）与 `period_source`
   （期间是原文印出还是报告身份继承），证据表新增 `context` 行；继承来的口径不再冒充原文。

## 1. 宏观架构与职责边界（§1）

- 两条提取路线保留（foundation16 与 standard），符合报告“先统一语义与事实，不先删路线”的顺序；
  阶段 2 已让两条路线输出同一 SourceFact，本轮未改动。
- 职责边界无新增耦合：本轮所有改动都落在既有层内（标准侧声明、构建脚本、公开投影、Console）。

## 2. 模型与提示词（§2）

- 未更换模型，符合报告“不应先换模型”的结论。
- “模型做语义选择、程序做事实读取”保持不变（阶段 9 结构优先，模型只处理行映射）。
- 未新增模型调用点；本轮所有新字段均由确定性数据生成。

## 3. PDF、DocumentIR 与检索（§3）

- 文字层直读确认为**共享能力**：`_read_text_layer` 对所有真实 PDF 生效，旧注释“仅 foundation16”
  已改正（本轮）。
- 选页可由版本化合同注入关键词组、中立事实按 IR 版本缓存复用，见[阶段 3](PHASE3_INCREMENTAL_EVIDENCE.md)
  的真实验收（同一报告第二次复用 180 条中立事实，未重读全本）。
- 覆盖状态区分 `covered / unconfirmed / out_of_scope / missing`；本轮修正了固定口径的匹配语义：
  **条款固定的轴不要求报告印出，只有印出不同值才算冲突**（静默不等于矛盾），
  避免“可再生”条款因报告未写“能源流向”而被判未覆盖。
- 未执行新的全本 OCR 实验：按报告原则，本轮不重复消耗模型调用。

## 5. 来源事实、数据库与科学数据产品（§5）

## 7. 分阶段规划（§7）与最终原则（§8）

阶段 0–14 的交付记录在 `docs/PHASE*.md`。本轮对阶段 1（合同统一）与阶段 4/5（科学表、证据分层、
标准中心视图）做了补强；未发现需要回退的阶段结论。

五条最终原则逐条对应：

1. 模型解释局部证据，不决定正式事实 — 不变。
2. 条款定义只有一份 — 固定口径已归一到标准侧，字典与目录同读一份。
3. 来源事实与条款映射分离，报告细分类不被覆盖 — `reported_dimensions` 与 `dimensions` 并存。
4. 数据库保存长期科学观测，Bundle 只是快照 — 投影与对账通过。
5. Console 围绕业务对象组织 — 主线四步 + 工具三项，无外部报告源。
