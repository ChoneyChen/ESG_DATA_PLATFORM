# ConsoleESG · 独立开发人员工作台

独立 React / TypeScript / Vite 应用，负责报告准备、定向提取、证据核对、审核、发布与运行诊断。公开数据展示由 PlatESG 承担。工作台拥有自己的页面、状态及构建，不嵌入旧工作台。

## 运行与验证

```sh
npm ci
npm run test
npm run build
npm run dev
```

开发入口为 `http://127.0.0.1:5180`。正式静态入口由项目启动器提供于 `http://127.0.0.1:18081`，三个服务通过同源代理访问。

| 前端代理 | 负责服务 | 默认上游 |
| --- | --- | --- |
| `/document` | 报告、连续 OCR→DocumentIR、会话、标准目录、唯一队列 | `18080` |
| `/targeted` | 固定 IR 版本、条款投影成果与原文证据 | `18180` |
| `/publication` | 候选审核、指标合同、口径、发布及冻结数据版本 | `8765` |

开发代理上游可通过 `CONSOLE_DOCUMENT_URL`、`CONSOLE_TARGETED_URL`、`CONSOLE_PUBLICATION_URL` 配置；生产代理由宿主服务管理。

## 页面与模块

| 路由 | 工作职责 |
| --- | --- |
| `/#/overview` | 实际活动队列、异常与最近报告 |
| `/#/reports`、`/#/reports/{asset_id}` | 第 1 步。PDF 资源表：按读取状态筛选，每行直接给出下一步动作，版本链按需展开；报告详情含概览、原文、处理与证据、提取、审核、发布记录 |
| `/#/processing` | 第 2 步。连续报告处理、固定证据版本、可恢复动作；缩略图 / 章节 / 问题索引、原文、对象详情三栏核对 |
| `/#/automation`、`/#/automation/new`、`/#/automation/{automation_id}` | 工具 · 批量报告、自动排序、整批预览、连续处理／提取／候选交付、暂停恢复与终态记录管理 |
| `/#/extractions`、`/#/extractions/new`、`/#/extractions/{session_id}` | 第 3 步。选报告即完成读取方式判断；输出范围、后端计划预览、单份或同范围批量提交；详情按“成果、来源事实、阶段与运行、交付审核”四页签组织，固定范围收在成果页内 |
| `/#/extractions/standalone/{job_id}` | 按聚合验证的历史独立任务身份，只读查看原投影；不自动恢复或新建父会话 |
| `/#/standards` | 按小号组织标准包；原编号、核心和主要条款、条件、关系、可编译与占位状态 |
| `/#/review`、`/#/review/{mapping_id}?report={report_ref}` | 第 4 步。来源证据、事实审核、映射审核及按指标合同生成的口径表单 |
| `/#/publication` | 第 5 步。真实发布阻塞、处理器状态、交付收据、重试、冻结版本、观测来源及修订 |
| `/#/runtime` | 工具 · 服务合同、唯一队列、模型及资源、存储依赖、可审查删除计划、回收站和恢复 |

`src/api.ts` 管理三服务请求及内存凭据；`src/state.tsx` 管理带身份隔离的数据读取、执行事件和轮询恢复；`src/pipeline.ts` 是页面读取路线的唯一措辞来源（选页、版面区域、文字层直读、视觉识别不可读页、结构证据、指标提取），页面不再各自拼接流程文案；`src/components/StepSpine.tsx` 是生产主线的唯一定义，每页顶部显示当前步骤与下一步，侧栏按同一条主线排列。`src/components` 保存共享操作、计划范围与证据浏览组件；`src/pages` 按职责划分页面。工程诊断放在可展开详情中，默认操作采用字段表单。

## 关键合同与行为

- 不需要粘贴任何密钥：在本机打开工作台时，数据平台把回环请求识别为本机操作员（读取、审核、发布、管理）。数据平台（8765）未启动时，审核、交付、删除与发布暂不可用，启动后自动恢复。从其他机器访问或脚本调用仍须 Bearer 令牌；数据平台设 `PLATESG_LOCAL_OPERATOR=0` 即关闭本机识别。详细操作见[数据生产工作台](../docs/PRODUCTION_WORKBENCH_20261010.md)。
- 自动生产用一个持久父计划冻结多份PDF、报告修订、标准范围和执行顺序，按序把子任务交给唯一队列。本轮使用本地模型；凭据不进入计划JSON，服务重启后候选交付等待重新连接。正式审核和发布仍独立。终态计划可归档恢复，不删除子任务或来源。
- 报告、处理、提取和队列列表直接提供管理、默认隐藏归档；批量整理先核查每项修订和允许动作。报告详情提供相关OCR／IR文件管理，提取详情提供原生会话缓存预检、回收和恢复清单。
- 保留主要清单的 49 个 ESRS 原编号：E1–E3 当前 16 项输出、后续 33 项占位。目录本身由后端提供；包内核心条款与平台主要条款分别表达，选择主要条款不自动纳入其它核心。
- 历史标准详情按明确包身份及内容版本只读，展示该版核心与原合同诊断，不继承当前批准状态。延伸选择同时检查其批准收据、父包版本和摘要；草稿及不匹配的新父版本不可选，历史批准不会自动传给新草稿。
- 执行前调用后端计划预览。改变来源、范围、模型或预算后旧预览立即失效。批量创建逐份记录成功及失败，失败不会撤回其它报告的成功任务。
- 选择报告即完成读取方式判断：系统先按文字层选页、版面区域直读文字并重建表格，只有文字层不可用的页（扫描页、图片表格、字体无法映射、倾斜文字）才调用视觉识别。已有兼容结构证据直接复用。指定结构证据版本是可展开的例外入口，不再作为每份报告的必经步骤；换报告即清除原指定版本。
- 报告库按读取状态（全部 / 未读取 / 可提取 / 有问题）筛选，每行只给一个主行动；读取版本、结构证据与删除管理收在展开区与“⋯”菜单里。提取设置默认只保留提取路线、完整度预设与模型方案三项，模型分配、云授权与资源预算收在高级设置。
- 16 项看板默认按条款包分组，可切换按业务领域；列可增删（原编号、指标、状态、原值、单位、期间、来源、来源行、口径标记）。展开任一行直接显示成员表与逐条证据，不再需要第二次点击。
- 报告身份来自明确登记字段；文件名仅用于寻找资产，不补充发布者、期间或测量主体。固定 IR 不可读时报告错误，不静默切到另一版本。
- 进度使用队列的结构化业务单位。没有可靠总量时显示阶段而不绘制百分比；预算不是完成率。墙钟时间、观察到的活动时间及睡眠 / 时钟调整分别显示。
- 证据使用真实页索引、对象 ID、单元格 `cell_id` / `col_index`。只在坐标单位和原点可靠时绘制位置；缺少几何的单元格仍在 HTML 表中准确高亮，不伪造位置。待处理和已解决人工问题分组独立保留。
- 候选来源使用后端 `evidence_location`：`state`、`asset_id`、`ir_run_id`、`ir_revision`、`pdf_available`、`ir_available`、`reason`。仅明确的能力 `true` 才启用原文或 IR；不根据身份字符串前缀推断存在性。合成和不可用来源显示保存的引文及原因。
- 已读取来源事实单独浏览，未映射表行及原属性仍保留；每页500条，使用后端固定报告游标继续读取。失败保留当前页和证据，重试使用失败的原游标；切换报告隔离旧请求与选择。累计已读不是PDF总行数，候选审核列表另有明确1000条窗口。
- 报告聚合的 `current_processing_evidence` 与 `historical_fixed_evidence[]` 分开显示。查看历史固定引用不等于其已通过本轮引擎 / 配置兼容检查。聚合 `standalone_jobs[]` 按任务身份去重，已有父会话投影保持原入口。
- 选中候选后先显示来源与审核表单，完整列表折叠并保留返回入口。页面只有一个 `main` 地标，证据区使用具名区域。
- 候选交付调用 `/document/api/console/report-sessions/{id}/deliver`，提交登记报告 `report_id` 与 `expected_revision`，展示逐投影持久收据和阻塞。正式发布需要独立的事实、映射及测量口径批准。
- 存档状态使用受 `read` 权限保护的 `GET /document/api/console/report-sessions/{id}/delivery-status?report_id=...`。后端核对固定 PDF、原生会话、子任务、成果摘要、SQL 批次及最新回执尝试；原生会话的旧 `database_status` 与本地 Bundle 数量不作为入库依据。当前成果、同一会话、同一报告 PDF 版本分别计数；发布数量固定最高已封存数据集版本。未知数量显示“尚未核对”，不显示为零。切换会话清除旧报告选择，迟到响应不覆盖新身份；断网保留带时间的上次结果并明确当前状态待核对。
- 审核、口径和发布使用内部合同 API。服务端鉴别操作人及权限；前端凭据仅放在当前页面内存和 Bearer 请求头，不进入 URL、本地存储或公开产品请求。
- 自动发布关闭时明确显示需要运行发布处理器。口径保存成功不代表观测已发布；发布状态由持久结果决定。
- 发布条件以中文显示，原代码放入诊断。报告筛选在候选API服务端生效，审核跳转保留报告身份；全局发布事件、收据及版本明确标为全报告/全平台范围。
- 归档 / 恢复使用后端允许动作及修订字段。存储删除先读取依赖并创建计划，再显示阻塞和确认原因；过保留期前不能执行永久清理。
- 操作预检 `allowed=false` 或最新 `available_actions` 不包含可用的当前操作时，确认入口和请求同时受到限制；服务端继续作最终验证。进度默认使用服务端中文标签，模型调用保留真实工具、角色、阶段及观测时间，睡眠 / 时钟调整单独展示。

## 验收边界

`src/console.test.tsx` 隔离 HTTP 进行合同和交互回归，覆盖原编号及范围快照、真实进度与睡眠、权限凭据、报告聚合 DTO、旧记录修订 0、明确来源能力、无几何单元格、审核详情聚焦、合同字段、候选交付、预检阻塞、历史 / 当前证据隔离、独立任务去重与只读路由、批量部分失败和跨资源身份隔离。测试不调用真实模型、不写入项目历史数据。

真实服务验收需由项目统一启动后进行：标准目录及详情 → 上传 / 登记报告 → 连续处理 → 明确范围预览及提取 → 查看阶段事实和缺口 → 交付候选 → 事实 / 映射 / 口径审核 → 手动或自动发布 → 固定版本及来源回查。构建或隔离测试通过不能替代此闭环。
