## 四层材料与连接

```text
原始IG3目录：1184原始行、原编号、条件、出处
  ├─ 小号标准包：完整语义、包内核心、依赖、ESRS2/MDR共用接口
  ├─ 平台字典：通用概念、版本、单位、测量身份、比较合同
  └─ 提取配置：49主要原编号；显式E1–E3范围产生16输出
        ↓ 冻结配置/字典/包摘要
原报告Session → 中性SourceFact + 所选Core + 原文证据
        ↓ 完整/partial Result Bundle + 明确报告身份的交付描述符
同一数据库事务：候选事实 + 映射 + 批次 + 范围快照 + 阶段审计
        ↓ 事实审核、exact/supports映射审核、人工测量口径
同一事务：独立审核决定 + 待发布outbox
        ↓ 最新审核状态 / 必要身份 / 单位 / 冲突 / 重述门槛
同一事务：不可变观测与原证据 + 封存数据集成员 + 事件确认
        ↓ FastAPI版本化读取
独立React平台 / 比较及排除 / 证据 / 版本化导出 / 后续分析
```

主要配置只激活所选输出和声明的计算依赖。单包核心按钮不等于平台主要。手动选择解除主要快照，可以形成显式候选；未纳入主要字典的候选不能自动发布。

`selection_snapshot`冻结profile版本/摘要、dictionary版本/摘要、原编号和package摘要。Session预览校验目录、包与选择集合，子任务携带同一快照。导入再次核验完整编译快照内容及每条输出是否在request范围内。解释、身份或范围冲突回滚整个候选事务。

真实导出使用`execution_status`，兼容旧`status`。明确completed且无partial、未完成或证据缺口才登记完整阶段。相同Core/同批次partial→complete追加manifest指纹并更新独立阶段状态，不产生新事实，也不把空输出变为数值。

## 数据库与服务边界

继续采用PostgreSQL SQL，一个物理数据库保存事实、审核和发布；模块分别登记自己的迁移。PGlite用于本地，`pg`用于服务器，同一事务始终使用同一连接。[node-postgres事务文档](https://node-postgres.com/features/transactions)。

FastAPI负责严格HTTP模型、OpenAPI和内部凭据门禁。Node常驻子进程复用已有导入器/PGlite，不逐请求启动命令、不开放任意SQL、不重复维护事实库。RPC串行、有截止时间；不确定写入超时后不自动重放。[FastAPI文档](https://fastapi.tiangolo.com/tutorial/first-steps/)、[PGlite API](https://pglite.dev/docs/api)。

| SQL对象 | 内容 |
|---|---|
| 既有`esg.esg_disclosures` / `structured_values` / `disclosure_sources` | 原事实、精确值/区间、原文及源身份 |
| `esg.review_decisions` | 事实/映射独立审核，语义关系与支持程度审计 |
| `esg.metric_definition_versions` | 指标版本、原编号、冻结定义及包摘要 |
| `esg.measurement_contexts` | 人工确认主体/期间/边界/方法/维度，只追加修订 |

| `esg.normalization_rule_versions` | 不可变的单位别名、倍率、精度政策及规则摘要 |
| `esg.observation_sources` | 原值/原单位/原文/审核引用的发布时快照 |
| `esg.publication_states` | 当前独立审核、发布状态和阻断原因 |

## 发布及比较合同

发布要求事实approved、映射approved且exact/supports、原编号在ready主要清单、实际包/摘要相符、物理来源存在、审核口径确定、必要维度满足、单位可解释、没有未裁决冲突。

任务默认主体、年份或指标预设方法不能补造源事实。范围2两种方法由审核确认；范围1＋2合计不能变成范围1；取水/耗水、污染物/介质、材料流及风险区域分别定义。

数字使用`numeric`及字符串API。明确倍率采用精确乘法；非终止十进制采用显式精度规则并保留原值。比率允许范围来自指标定义，可再生占比0–1，不强制所有ratio都属于占比。

当前单位规则为`esg-units-1.1.0`，覆盖这16条款需要的MWh、tCO2e、tonne、m3、ratio及明确中文倍率。来源单位缺失或未知时阻止发布，审核选择规范单位不能替代来源倍率。规则升级通过迁移0007、唯一outbox事件和新观测身份重新核查当前记录；旧观测及历史数据集不改写。

缺比较方法等条件的合法观测可展示并说明，不能进入严格比较。定性与区间不制造点值排名。比较针对请求的数据版本核对定义、期间、边界、主体类型、方法和专属维度；多个口径组必须显式选择，返回所有排除原因。

同一身份有不同值时阻断当前发布；同一规范值有多支持来源时形成一个修订保留全部来源。晚到审核事件处理最新状态，不重发已撤回事实。重述须显式指定被替代观测并核对完整测量身份；历史数据集继续可读。

覆盖审计逐期间、主体保存。发布观测固定于数据集；候选与人工缺失为当前状态。响应区分`publication_as_of`与`coverage_as_of`，不把2024发布当作2025完整。未来需要完整历史覆盖研究时应封存覆盖成员；本轮未冒充已有此能力。

## 验收及后续

运行、配置、metadata、候选交付、审核及失败回执操作见[PlatESG指南](../../PlatESG/README.md)。本轮没有批准历史中国石油原事实、没有调用真实/云端模型、没有生产发布。

工程样本为两家合成企业×两个期间×16条款，共64观测，验证候选→审核→口径→发布→版本→比较/排除→原文→导出。合成测试不证明真实提取精确率或召回率。

回归覆盖范围锁与核心/主要区分、篡改摘要、输出越界、导入原子性、精确数值、单位与身份错配、独立映射、区间/定性、冲突/撤回/重述/重试、版本/游标/导出、逐期覆盖、空库和页面状态。

本轮共541项通过：标准包及定向后端384、提取控制面70、平台Python合同35、平台数据库服务6、结果库20、前端26。结果库另有1项既有partial导出样本依赖测试按条件跳过。前端TypeScript/Vite构建和格式检查通过；浏览器核验了实际API页面、跨期间拒绝混比、选定期间后纳入、原编号与百分比换算依据。合成数据库与既有真实候选库分别存放，早期合成预览库已另存归档。

生产PostgreSQL、负载/备份恢复、多人认证及真实报告金标准尚待验收。V1按全映射重算发布、全快照再筛选，适合当前小规模试点；扩大后应按受影响身份增量处理，在SQL层分页，保持同一合同。

后续顺序：人工核对首份真实报告的16条款及各自多维披露 → 审核发布 → 第二企业/第二期间比较及排除验收 → 扩展33条与行业配置。真实试验要记录证据、错误及分母，不能以演示代替验收。
