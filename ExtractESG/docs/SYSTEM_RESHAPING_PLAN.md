## 1. 根本任务：最终需要得到什么

### 1.1 产品任务，而不是模型任务

输入是 ESG/可持续发展 PDF、一组用户选择的标准要求、允许使用的模型与费用/资源预算。
输出是口径明确、来源可复现、能够跨标准复用和进入数据库的报告事实，以及所选标准的覆盖与缺口。

系统不是把每个 datapoint 填成非空，也不是让某个模型把整份报告转成巨大 JSON。
共享表理解的首要目标是使行义、列头、期间、实体和方法保持一致；调用量只是成本观察项。

用户的正常操作应是：选择报告/文件夹 → 选择跨标准指标 → 选择语义引擎与预算 → 启动 → 查看结果或处理具体问题。
用户不应先理解 OCR run、IR run、review provider、semantic provider 和多个互相重叠的重跑入口。

### 1.2 最终数据的五个层次

| 层次 | 必须表达的内容 | 不能混淆的边界 |
|---|---|---|
| 源证据 | PDF、页码、物理对象、行列/单元格、完整表头、摘录、图片位置 | OCR 观察不是经模型理解的 ESG 事实 |
| 报告事实 | 原值/陈述、单位、期间、实体/角色、边界、测量类型、适用语义轴 | 标准要求中的固定标签不是报告披露的证据 |
| 标准映射 | 一条事实适用哪些要求、理由、方法/分类依据、不确定性 | 一个源事实映射多项不增加源事实数量 |
| 计算与关系 | 既定公式、操作数、身份对齐、重复披露/替代单位关联 | 派生值不是直接披露；汇总视图不是新的测量 |
| 产品与数据库 | 可读表格、机器导出、入库草稿、审核记录 | 执行完成、合同通过、事实批准和正式发布不同 |

一条定量事实至少保留原始行主题、完整列头、原值与单位、期间、主体、主体角色、物理位置及解释版本。
Scope、方法、能源载体、类别、场地等按事实适用性保留；未知身份可以为空，但必须显示缺失，不得从请求补造。
一条定性事实必须是真实可读陈述或列表成员，不能用年份、数值或第一个证据字符串代替。

同值、同年、同指标不证明同一事实；同一实体的总量与组成项也不能混算。
GWh/TJ 等原始展示各自保留，只有身份和披露关系支持时才能关联到一个逻辑测量，不重复求和。

### 1.3 质量目标及明确非目标

质量必须分别观察：正确证据召回、源行语义、单元格身份、标准适用性、定性可读性、重复关系、未找到结论、恢复能力。
非空指标数量、合法 JSON 数量、模型调用数量均不能单独代表质量。

本次重塑不扩展到 CrawlESG、企业主数据、全报告 Full Harvest、多机调度或行业评分。
不增加一套与现有 `esg_database` 并列的事实数据库，不引入多 Agent 集群作为默认，不执行模型生成的任意代码。
不新增繁琐哈希链或以大量 ESG 语义 Guard 代替模型判断。

## 2. 从需求推导：宏观链路需要什么

### 2.1 必要能力，而不是固定十一阶段全量前置

| 必要能力 | 为什么需要 | 正确边界 |
|---|---|---|
| 文档输入与身份 | 避免报告串用，支持重用原件 | 原件不改；公司/年份来自明确元数据，不靠文件名作权威推断 |
| 可阅读、可定位的证据 | 模型要理解表、正文、脚注，还要可追溯 | 文本、表结构、图片是互补能力，不要求全部对象先达到最高质量 |
| 标准语义与关系 | 明确主量、延伸、方法、计算和视图 | 标准包不存模型、Top、prompt 或执行顺序 |
| 报告级检索与阅读 | 同一表可服务多个要求；独立分支不能漏 | 排名影响访问顺序，不直接否决未披露 |
| 模型语义理解 | 识别行义、表头、实体、方法、类别和证据不足 | 小任务理解；程序不伪造语义标签 |
| 标准映射与补证 | 已理解事实和标准有多对多关系 | 模型根据具体缺口决定下一次查询/阅读 |
| 结果编译 | 稳定原值展开、公式、身份、排序和来源 | 不要求模型反复抄数、自由算术或维护主键 |
| 持久化执行 | 长任务可取消、恢复，局部失败不报废成果 | 程序管理状态、资源、权限和预算，不由模型自由决定 |
| 产品与入库接续 | 从结果到数据库有明确审核边界 | 同一后台结果驱动网页、导出和入库草稿 |

### 2.2 目标主线

```text
报告与标准选择 / 数据传输许可 / 预算
  → 创建报告级 Session、固定输入及版本
  → 基础 OCR/IR 与按能力可消费的证据
  → 发现主表、独立分支、方法和对账证据
  → 模型理解源对象，程序展开原值，形成统一报告事实
  → 模型将源事实映射到相关小指标族
  → 对具体缺口补查、读局部图或请求局部修复
  → 确定性计算、关系合并、Core 投影和统一展示
  → 结果包 / 数据库候选草稿 / 独立审核
```

这是一个持久化任务内的工具型 Agent，不是每个条款一个 Agent。
模型有语义决策和证据动作选择权；程序掌管工具作用域、费用授权、执行资源、来源合同和保存。

## 3. 当前真实链路与架构审计

### 3.1 当前执行路径

07 计划依次派发 OCR、IR、各标准包独立抽取任务。IR 构建默认执行复核；抽取固定一个包，
按指标准备检索和 packet，在指标循环内部启动/复用主题 `DisclosureSession`。
现代主题执行真实的导航—理解—映射小循环；成熟污染物及兼容模式执行直接填表。
之后统一做合同物化、必要的家族复判、派生、组织与导出。

不能把它说成完全规则式、没有 Agent：四种工具和模型决定下一步已经存在。
但也不能说已经完成报告级多模型系统：任务、源事实字段和模型角色仍受旧合同约束。

- 模型理解与映射的小合同、稀疏字段、定性 assertion、IR 原值展开。
- Grounding 的真实来源边界、Core 六类结果及单指标合同失败隔离。

## 4. 新架构：角色、任务、事实与状态四个共同合同

### 4.1 模型角色

| 角色 | 职责 | 默认产品配置 |
|---|---|---|
| 程序编排器 | 状态、依赖、预算、资源、取消和工具执行 | 不选择模型 |
| 语义主脑 | 导航、源对象理解、标准归属、缺口与冲突裁决、必要视觉复核 | 本地 Qwen3.5 或明确选择的七牛通用 VLM |
| 专用抽取器 | 已验证污染物配方、小规模结构抽取 | NuExtract 或既有已验证配方；高级设置覆盖 |
| 检索服务 | 对象索引、关键词、原始及改写查询向量 | 自动管理，不判断披露适用性 |
| OCR | 布局、文字、网格和坐标 | 系统级配置，API 回退需许可 |
| 结果引擎 | 原值展开、公式、来源绑定、Core、关系与排序 | 确定性代码 |

NuExtract 不是被定义为“不会理解”；专用角色是项目分工，不是模型能力的绝对限制。
不强制 Qwen 后接 NuExtract 抄数。可靠 IR 已有数字时直接展开；专用模型仅处理确实适合的任务。
成熟污染物保留实际验证过的 Provider/模板/检索组合，不因主脑默认变化而悄悄替换。

Provider 共用调用结果与遥测合同，但输入编译分离。不能让 Qwen 业务类继承 NuExtract 业务假设。
局部读取、映射和复杂结构解释可有不同预算；不以全局关闭/开启 thinking 代表智能程度，也不无限扩大输出。
复杂语义任务的推理能力配置需通过业务样本判断，最终只保存可审阅结论和证据理由，不要求输出长推理文本。

### 4.2 报告任务与证据版本

新增 `ReportExtractionRequest`，包含报告输入、跨包所选要求、角色配置、证据预算和云端授权。
已存在 IR 与 PDF 起步使用同一请求；报告级 `ReportSession` 持有源事实和缺口，不按包创建相互隔离的主任务。
标准包仍独立快照，Core/Bundle 可以逐包编译，避免不同标准 elements 混写。

入场快照使用明确 ID/版本；保留策略对排队、运行和需恢复 Session 的引用提供 pin，禁止悄悄重定向已冻结输入。
Agent 请求局部 IR 修复时创建子 revision，Session 明确记录证据版本转换和受影响对象，旧事实仍指向原来源。
只使受影响解释/映射失效，不能在同一 ID 下覆盖旧证据，也不能无记录地混用修复前后数据。

### 4.3 最小共同合同

| 合同 | 用途 |
|---|---|
| `RoleConfig` | 主脑、专用能力、检索、OCR、授权和资源策略 |
| `ReportSession` | 固定选择/快照、当前证据版本、进度和依赖 |
| `EvidenceObject` | 物理或逻辑阅读视图、成员来源、可用能力 |
| `SourceFact` | 标准无关报告事实、原始身份和解释版本 |
| `RequirementMapping` | 事实到要求的适用性、依据和限定范围 |
| `EvidenceGap` | 缺口类型、对象/行/列/指标影响范围、下一步动作 |
| `StageOutcome` | 执行状态、可消费产物、缺口、错误及后续条件 |
| `AvailableAction` | 动作类型、作用域、条件、调用入口和代价提示 |

这些是少量必要共同合同，不是给每个内部函数增加一个抽象层。
保留现有 Core 六类结果，将它作为标准投影；不因 Agent 化重造 Core。

### 4.4 中性源事实与唯一投影

表理解输入只包括对象、表头、脚注、相关正文和中性语义轴；不能再使用某包 elements 的全集作为源理解字段合同。
模型解释行/列，程序绑定原值；定性段落独立生成真实陈述。模型可通过明确视觉来源纠正或补读具体单元格。

源事实保留 raw/normalized 并存：报告中的“紫金、藏格、合计”不强行塞入报告边界；方法无证据则未知。
标准外但有据的公司特有分解进入原始开放维度，能够类型化时再归一化；不能因字段枚举有限而丢掉报告含义。
映射阶段读取相关小图和语义卡。一个对象解释可支持多个包；新增指标只补映射或缺证据，不重复读数。
标准专属枚举和固定分类只在映射/投影阶段写入，不反写源事实。

定量展开、定性断言、任务级固定元素统一通过一个投影编译器进入物化器。
现有直接填表的已接受输出也可通过适配器形成源事实，不要求额外模型调用。
同 ID 同内容幂等合并；同 ID 不同内容局部合同失败，不静默吞掉，不拖垮其他指标。

### 4.5 缺口驱动工具循环

保留并收束当前四工具，补充：读取逻辑表/表头/脚注、局部图、指定单元格、标准卡、局部修复和标准公式。
工具一次只执行有界操作，返回新增事实、解决缺口、剩余缺口和可选动作；无需将全报告或全部 35 项送入每轮。
报告文字与图片只作为证据，不能覆盖任务选择、工具作用域或云端授权；模型动作仍通过既定工具执行，不执行报告内指令。

导航根据真实缺口选择行动。没有方法证据就搜方法；缺一列就补读那列；映射格式错只修映射；网络失败不重新判断语义。
新主线的冲突复判使用同一映射工具，带冲突案例和小指标族，不再另跑一套整包语义程序。
相同无进展动作以结构化行动与结果比较；改变查询/证据/角色或明确停止，不建输出哈希链。

预算区分初始发现、实际阅读、补漏、单调用和总时间；用户看到完整度预设，高级设置才显示详细参数。
有界停止只代表仍有缺口，不代表报告未披露。账户错误停止相关通道；不转换为业务 not_found。

### 4.6 Embedding 与本地模型资源

对象索引按固定 IR 复用；初始查询小批量 embedding，索引矩阵不依赖视觉模型驻留。
Agent 产生新语义查询时，检索服务对新 query 生成/缓存向量，不继续冒用原指标向量。
本地资源管理器统一获取/释放重模型，必要时在持久化动作边界暂停主脑、批量检索再恢复。
避免逐单元格 Qwen→NuExtract→Qwen 的加载震荡，不同时驻留多个本地重 VLM。

所有真实 OCR/IR/抽取 API、CLI 和队列使用同一执行准入与监督，旧接口只是适配器。
重启接管、硬截止、取消、心跳和无进展检测保留，不能靠放宽超时掩盖执行脱管。

## 5. PDF、OCR 与 Document IR 的需求导向改造

### 5.1 保留基础取证，停止默认全报告语义增强

低分辨率可渲染预检与正式证据页图用途不同，不能机械删掉其中一个。
OCR 版面、表格网格、原生文本交叉检查、来源坐标都服务可追溯事实，应保留。
可复用的原件/页图/布局取证由资产层管理，不为每次抽取重新生成。

默认先产出基础可读 IR 和对象质量。完整图表语义重建、无关跨页增强等作为显式可选工作，
不因 07 启动就无限纳入本轮必要任务。真正影响所选证据的修复仍需执行。

### 5.2 可用性按对象和能力表达

分别描述：原页图可用、正文可用、单元格网格可靠、表头不确定、来源不可定位。
标题树可疑不应自动等于原页图/正文不可读；一张图表有问题不应删除同页正确的排放表。
模型可以读取来源可靠的局部图片，而不必强制依赖不可靠 OCR 网格。
仍不得把未修复对象显示为“结构已验证”；全局身份、文件或来源损坏继续阻塞。

短期优先修正局部/全局问题分类和消费合同，再从整页排除迁移到对象/能力粒度。
LogicalTable/Spread 作为逻辑阅读视图，继承表头/脚注，每个成员仍定位物理 cell/page。

### 5.3 局部修复与保存也应局部

先修 A07：只有真实返回且结构可绑定的行标记成功；缺失行与表头缺口独立保存并能再次读取。
再修 A08：缺口只影响相关对象/行列及映射，不将一个结构问题传播给整主题全部指标。

短期合并同轮独立决定，避免每个按钮复制整份报告；中期使用共享不可变页图资产和对象增量修订。
导出可生成自包含 IR 包。旧包继续可读，不能先删除复制机制而破坏来源引用。
资产共享和 retention/pin 一起实施，不另加对象存储平台或复杂哈希框架。

## 6. 标准包：保留关系图，完善语义用途

标准包继续描述含义、事实粒度、身份轴、适用条件、证据需求、兄弟区别、公式和展示关系。
运行计划按报告证据动态形成；主题是导航组织，不是不可跨越的执行分区。
当前单 `disclosure_topic` 可以保留为主要展示分组；运行时证据簇允许多主题成员关系。
不能将形式上无循环的图等同于标准语义已经批准，新增关系应绑定相应标准依据，而不是统一复制一项 source_refs。

### 6.1 E1-6 的主次结构

| 主线 | 延伸与上下文 |
|---|---|
| 07 Scope 1 | 08 排放交易覆盖、17 生物源 |
| 09/10 Scope 2 并列方法 | 18–23 合同工具、24 生物源；必须有各自口径依据 |
| 11 Scope 3 | 25 数据来源、26/27 纳入/排除、28 生物源；类别身份及框架说明 |
| 14–16、29 方法 | 解释相关主事实，不代替数值 |
| 33–35 营收及对账 | 支持 30–32 强度/分母相关要求 |
| 12/13 总量，30/31 强度 | 直接披露优先；满足明确身份、方法、单位和分母依赖后派生 |
| 01–06 结构/汇总 | 已有事实视图优先；真正独立成员或说明仍提取 assertion |

独立延伸披露不因主量缺失被跳过。单选派生项时，内部读取必要依赖证据，但不擅自增加用户所选标准输出。
总量、小计和类别成员都可保留为报告事实，但在标准投影和计算时区别粒度，不能重复汇总。
GHG Protocol/ISO 分类必须来自报告证据，汇总视图本身不证明框架适用。

### 6.2 E1-5

能源消费主表统一理解：总能源、来源结构、化石载体、购入/自发、消费/生产、实体角色。
能源生产、强度、行业口径及营收保持独立证据需求；比例、变化量、装机容量不与消费量混在同一填表任务。
原始单位、量级和替代展示保留；需要计算时由既定公式执行，不让模型临时算术。

### 6.3 E2-4

02/03/04 保持独立介质语义、既有来源合同和成熟抽取配方。
接入报告 Session 时先适配成果，不改变成熟提示词和召回边界；复杂扩展项再按证据形态启用 Agent。
不能以新模型可用为理由默认覆盖三个好路径，也不能以回放通过声称新模型业务质量通过。

### 6.4 版本与静态检查

当前三个 `2.0.0` 均为 draft。仅真正语义/合同变化发布新版本，不为换引擎机械升级包版本。
发布后旧编译目录退出新任务目录，源包、退役版本和历史快照保持可读；不原地覆盖内容不同的同版本。
检查引用、基数、事实拥有者、依赖/替代/关系结构和公式输入，不重复制造运行时语义 Guard。

## 7. 状态、结果表与数据库接续

### 7.1 一套状态服务

执行轴：queued / running / interrupted / failed / cancelled / finished。
成果轴：usable / partial / needs_confirmation / no_evidence_in_bound / not_evaluated。
具体 API 值在合同实施时定稿；不能让页面各自翻译同一状态。

`StageOutcome` 同时返回可消费产物、有效作用域、缺口和错误。IR partial 有可用证据就可推进；
抽取 partial 保存有效事实并进入待处理，不将整报告成功步骤重跑。是否穷尽报告另行记录，不能由 completed 推断。

后端统一返回 `available_actions`：恢复未完成动作、补查、换对应角色、局部修复、重建合同、接受有限覆盖等。
每个动作说明范围、是否调用模型、是否新增费用、需何种批准。前端不靠错误文字或旧 reason 枚举猜按钮。

### 7.2 清晰的事实表

后台统一列序：源行主题 → 期间 → 实体 → 实体角色 → Scope/方法/类别 → 数值/陈述 → 单位 → 证据。
报告事实、标准覆盖、证据三视角读取同一合同；标准专属元素放详情，不再让原始 elements 表成为唯一主视图。

完整身份应按适用 identity_axes 判断；出现 source_row_label 不能自动算完整。
不同物理来源只有明确重复披露关系才合并成逻辑测量；数值相同或换算接近只是候选信号。
保留原记录、多处证据和替代展示，推测的关系标成待确认，不静默影响求和。
网页、JSON、CSV、XLSX 与入库适配全部采用后端组织结果。

### 7.3 接现有数据库，不另建事实库

现有 `esg_disclosures` / `structured_values` / `qualitative_claims` / dimensions / sources / mappings 是正确基础。
先实现真实结果→candidate 草稿导入及批次/来源记录，再提供有操作者与理由的批准动作。
源行列、逻辑测量/替代展示、派生依赖和公式版本按需补新 SQL migration，不修改既有迁移。
定性陈述不能机械复制成库里的主谓宾三字段；范围值也不能被 API 伪装成有单点数值的可计算量。

当前库只有 approved 对外视图门槛，尚无正式 publication 服务。事实 approved 与映射 approved 分开；
正式发布版本/权限另行建设。前端未接入时明确“结果包已生成，尚未入库”，不显示虚假的发布完成。

## 8. 前端产品与代码组织的收束

### 8.1 五个业务入口

| 新入口 | 合并/保留原能力 |
|---|---|
| 报告库 | 01＋02＋03；OCR/IR 历史、页图、逻辑表放报告详情的文档与证据 |
| 提取任务 | 05＋07 唯一创建器，已有 IR 为同一向导高级输入 |
| 结果工作台 | 06；报告事实、标准覆盖和证据 |
| 待处理 | 04 的人工决定/局部重试/受限继续等；系统故障与人工内容判断分开 |
| 系统设置 | 角色、云授权、解析/资源健康、缓存、技术诊断 |

普通创建只选报告、跨标准要求、语义主脑、完整度/授权。预览必须来自后端真实计划：角色、内部依赖、复用输入、预算、已知证据限制。
普通选择只有本地 Qwen 或七牛语义主脑；NuExtract 不再与主脑并列。高级对照保留，但不是第二默认主链路。
运行主进度为“准备文档—理解披露—补充证据—整理事实—形成结果”，工程阶段按需展开。
事实可用后即时可查看；完整审计 JSON/Guard/ID/模型输入按需加载，不淹没主表。

### 8.2 前端代码只保留一份共同逻辑

沿用原生 ES modules，不为此次升级强行引入框架。
统一 API client（地址、超时、错误、取消）、任务状态 store、标准选择器、角色配置、合法动作组件及订阅/轮询管理器。
同资源请求去重，页面离开退订；活动详情按状态 revision 增量刷新；网络失败不得返回空列表冒充没有结果。
业务页只消费服务。迁移完成删除旧请求构造、状态翻译和页面独立 timer，不保留新旧两份默认实现。
旧 01–07 书签可跳到新业务页；技术能力不因为默认导航收束而丢失。

### 8.3 后端逻辑边界与目录迁移

先实现共同合同和业务边界，再移动目录，避免同时改 import、启动路径和所有业务逻辑。
目标边界：平台控制面/工作台、文档证据生产、报告事实与映射、标准语义、结果编译、模型运行时、数据库适配。

- 控制面不应长期藏在 Document IR 生产者内部；可最终独立到 ExtractESG 平台层。
- 文档模块只生产证据和修订，不定义最终 ESG 事实。
- ReportSession/SourceFact/Gap 属于报告提取域，不属于每标准 packet 或前端。
- 模型运行时共享加载/遥测/截止基础，Provider 分别编译协议；不复制两套 worker 生命周期。
- 标准包没有运行脚本；数据库不复制企业主数据。

迁移一次完成一种职责，旧 route 做薄适配；不要同时保留两个 coordinator 或两个 source fact 真相源。
无需先建立通用插件平台、复杂事件总线或新的 Agent SDK。只有现有工具引擎确实不足时再引入依赖。

## 10. 有限而有业务意义的验收

### 10.1 工程验收

- 同报告跨三个标准创建一个 Session，各包投影可独立导出。
- 角色配置、实际 Provider 和调用任务完全一致；没有强制二次抄数。
- 新查询有对应查询向量；本地重模型由一个资源管理边界调度。
- 重启/取消/截止保存有效成果；恢复仅处理实际未完成对象/行/映射。
- 局部 IR 缺口不删除同页无关好证据；源定位损坏仍被正确阻止。
- 未选依赖可作为内部事实读取；所选结果集合不被扩大。
- UI 网络错误、空目录和无覆盖区分；隐藏页不持有独立全量轮询。
- 结果网页和所有导出身份/顺序一致；入库为 candidate，批准有独立记录。

未来实施只做与变更直接相关的小型合同/假模型验证和必要历史回放，不重复执行大套无关检查。
本次方案审计没有执行这些验收，不能把退出条件写成已通过。

### 10.2 真实报告业务验收

由用户发起真实任务，保留调用输入/输出与证据。重点样本为紫金宽能源表、Scope/方法表、定性方法、营收对账以及成熟污染物。
至少核对：位置法不串市场法、生物源不串总排放、期间/实体/角色完整、总量不重复组成项、强度分母正确、定性陈述可读、替代展示不重复求和。
分别记录正确证据进入模型、语义判断、身份、完整性和恢复成本，不预设固定 Top 2/3/5 最优，也不保证调用必然更少或耗时必然下降。

已有历史记录中的两份紫金 E2-4 各 106 条（空气 82、水体 24）仅是兼容保护样本。
越秀和完整土壤样本需补齐；不能声称完整三介质回归或新模型效果已经验收。
标准包仍为 draft，需真实业务验收再批准；模型裁决和来源/合同通过不能自动等同数据库 approved。

## 11. 本次决策摘要

1. 系统最终围绕报告事实，而不是条款循环和模型下拉框。
