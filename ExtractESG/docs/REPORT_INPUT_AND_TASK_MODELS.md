# 报告输入与按任务选模型

更新：2026-10-14。本轮范围是新建定向提取的来源选择和实际模型选路。平台主要条款仍保留完整 49 个原编号，当前 E1–E3 的 16 条原编号、包内核心与平台主要的区分均不改变。

## 应该选择什么

正常入口先选择报告。PDF 是报告的原始资产；OCR 是页面识别成果；DocumentIR 是由识别成果形成、供提取引用的结构证据。三者是上下游关系。

1. **自动准备证据并提取（默认）**：提交报告资产 ID。后端根据文件指纹、引擎版本、处理配置和证据能力检查已有成果，复用兼容版本；缺少成果时自动排队完成 PDF → OCR → DocumentIR → 所选条款提取。选择 PDF 并不跳过 OCR 或 DocumentIR。
2. **使用这份报告已有的结构证据**：先选报告，再从它所属 OCR 下选择明确的 DocumentIR 版本；只提交该 IR ID。跳过页面识别和结构构建。更换报告会清除原固定版本。
3. **多份报告**：每份报告独立采用自动准备、独立预览和创建，共享本次输出范围和模型选择。
4. **高级：历史结构证据**：原 PDF 已移除、结构成果仍可读取时使用。仅选择结构证据所属报告及版本，不同时选择另一个 PDF。

版本关联依赖明确的资产 ID、PDF 指纹及 OCR/IR 引用，不能根据报告标题、文件名或相似名称建立关系。固定版本不可用时保留明确错误，不能静默换成最新版本。完整证据与有限证据分别声明；有限版本还需要其 policy 和用户允许条件都满足。

## 从任务角度评估模型

已安装配置包含 Qwen3.5-9B-4bit、NuExtract3-mlx-4bits、PaddleOCR-VL-1.6；本轮只检查配置文件和权重存在性，没有加载模型、下载模型或运行真实报告。

| 模型 | 官方明确的能力 | 当前产品的任务位置 | 选择判断 |
|---|---|---|---|
| Qwen3.5-9B | 图像与文本理解、推理和文档理解 | 报告理解、来源规划、事实解释、结构视觉复核、模板抽取 | 默认统一理解与提取。覆盖当前所需任务，允许减少模型切换；是否更快、更准仍需实测 |
| NuExtract3 | 4B 多模态推理与结构化抽取，支持文本、图像、JSON 模板及文档 Markdown | 可选模板抽取、专项处理和结构视觉复核 | 不能因为名字叫“抽取模型”就强制加入；也不能把它当成旧版纯文本 NuExtract。仅在对应任务有收益时选用 |
| PaddleOCR-VL-1.6 | 面向文档页面的识别和解析 | 已接通的 OCR 页面、表格、布局和位置输出 | 目前保留为页面识别引擎，原因是完整证据输出链已接通；不据此宣称它在每种视觉任务都优于 Qwen |

官方能力依据：[Qwen 模型卡](https://huggingface.co/Qwen/Qwen3.5-9B)、[NuExtract3 模型卡](https://huggingface.co/numind/NuExtract3)、[PaddleOCR-VL-1.6 模型卡](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6)。上表“选择判断”是结合项目实现的工程判断。官方公开榜单不等同于本机 4bit 模型在中文 ESG 报告上的准确率，不能用不同榜单或参数大小直接宣布胜负。

**Qwen 能处理视觉输入，但“全部视觉步骤都换成 Qwen”尚未完成。** 当前可以将理解、提取和启用的视觉复核全部交给 Qwen。原始 PDF 页面的 Qwen/NuExtract OCR 适配器仍待实现：必须输出可核对的页面、布局、表格、单元格、单位和位置，并适配现有 OCR → IR 合同。模型返回 Markdown 或 JSON 本身不能替代这些证据。界面相应 OCR 选项明确禁用，后端也拒绝将它们当成可执行 OCR 引擎。

检索用 Qwen Embedding 负责向量检索，与视觉理解角色不同；统一理解方案无需用生成式视觉模型替换检索模型。

## 已提供的选择

| 方案 | 页面识别 | 启用后的视觉复核 | 理解与事实解释 | 模板抽取与专项处理 |
|---|---|---|---|---|
| Qwen 统一理解与提取（默认） | 本地 PaddleOCR | Qwen | Qwen | Qwen |
| Qwen＋NuExtract 混合 | 本地 PaddleOCR | Qwen | Qwen | NuExtract |
| 按任务自定义 | 本地 Paddle、授权云 Paddle、授权的本地优先回退 | 本地 Qwen、NuExtract 或授权云视觉模型 | 本地 Qwen 或授权云视觉模型 | 本地 Qwen、NuExtract 或授权云视觉模型 |

“模板抽取”不代表所有事实都一定交给该角色；支持报告语义处理的条款由理解角色解释和映射，专用角色用于其实际承担的模板任务。当前 NuExtract 未开放为报告规划主脑，这属于产品协议接入范围，不是对其官方推理能力的否定。

必要模型复核和额外视觉复核分别可选；新界面默认关闭，以优先推进基本链路。关闭不意味着忽略证据质量：不可用部分仍受证据能力和引用检查限制，缺口仍保留，正式发布仍需要审核。固定已有结构证据时跳过本次 OCR 和结构复核，不改写原版本。

云选项需要明确授权和对应凭据；没有凭据的实际云准备阶段在创建任务前阻塞。本地明确选择不会静默切换成另一提供方。只有用户选择并授权的本地优先 OCR 允许既有 API 回退机制。

## 前后端如何保证选择生效

- `role_config` 唯一声明理解角色与专用角色，新增可选 `model_plan` 声明页面识别和视觉复核配置。
- `GET /api/pipeline/model-task-options` 返回实际配置的模型注册名、任务选项、权重文件存在性和未接通原因；此接口不启动推理。
- PDF 预览与创建使用同一处理配置，队列执行采用该报告的 `processing_config`；不能只改变界面文案。
- 新任务预览确认注册模型名；创建时冻结角色名，随后验证提供方和模型路径匹配。两个角色选择同一个 Qwen 时共用底层模型，角色预算分别记账，不创建 NuExtract，不因角色切换卸载共享模型。
- 改报告、证据、输出范围、模型或运行策略会使旧预览失效。已有请求未声明 `model_plan` 时保持原默认与序列化形式。
- 输出分别记录期望与实际提供方、模型名，便于检查执行是否与计划一致。

## 下一次真实效果比较的标准

由用户选取新的独立报告，比较同一页、同一条款和同一证据条件下的数值、单位、年度、主体、方法和证据位置正确率；再比较 JSON 合同通过率、重复修复次数、耗时、峰值内存及人工修改量。清晰文本、复杂表格和低清扫描页分别统计。

若 Qwen 在某类任务中质量达标且成本更好，统一采用 Qwen；若 NuExtract 在模板任务中有明确收益，再启用混合。新增 Qwen OCR 后也需按同一证据标准比较。未取得这些结果前，不承诺某个模型全面最强。

本轮合成检查与本机接口检查验证工程选路和交互，不是上述真实报告效果验收，也不使用中国石油失败中间结果作为基准。
